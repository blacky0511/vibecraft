# 서브에이전트 작업 지시서 템플릿

메인 에이전트가 서브에이전트에 작업을 위임할 때,
반드시 이 템플릿 구조로 프롬프트를 정제하여 전달한다.

## 템플릿 구조

```markdown
## 작업 지시서

### 목표
{한 문장으로 이 태스크가 달성해야 할 것}

### 맥락
- 프로젝트: {프로젝트명}
- 기술 스택: {언어, 프레임워크, DB 등}
- 현재 브랜치: {브랜치명}
- 관련 계획서: {docs/plans/파일경로 또는 "없음"}

### 작업 범위
{구체적으로 수행할 Step 목록. 각 Step에 대상 파일 경로 포함}

1. `경로/파일명` — 할 일 설명
2. `경로/파일명` — 할 일 설명

### 기존 코드 참고
{수정 대상 파일이 있으면 핵심 패턴을 요약해서 전달}

- 네이밍: {camelCase / snake_case / PascalCase}
- 에러 처리 방식: {try-catch, Result 패턴 등}
- 기존 유사 코드 위치: {참고할 파일 경로}

### 제약 조건
- 들여쓰기: {2칸 / 4칸}
- 언어: {한국어 주석, 영어 변수명}
- {프로젝트별 추가 제약}

### 성공 기준
{이 태스크가 "완료"로 인정되려면 충족해야 할 조건}

- [ ] {구체적 기준 1}
- [ ] {구체적 기준 2}
- [ ] 모든 테스트 통과
- [ ] 기존 코드와 스타일 일관성 유지

### 하지 말 것
- 작업 범위 밖의 파일 수정 금지
- 불필요한 리팩토링 금지
- 새 의존성 추가 금지 (필요하면 메인에 보고)
```

## 정제 규칙

메인 에이전트는 서브에이전트에 프롬프트를 넘기기 전에 다음을 수행한다:

### 1. 맥락 추출
- 현재 대화에서 프로젝트 정보, 기술 스택, 경로를 수집
- CLAUDE.md, package.json, build.gradle 등에서 프로젝트 규칙 확인
- 계획서가 있으면 해당 Step의 상세 내용 포함

### 2. 파일 경로 명시
- "이 파일 수정해" 대신 **절대 경로** 또는 **프로젝트 루트 기준 상대 경로** 사용
- 참고해야 할 기존 파일도 경로 명시

### 3. 패턴 요약
- 수정 대상 파일의 코딩 스타일을 2~3줄로 요약
- "기존 코드처럼 해" 대신 구체적 패턴 명시

### 4. 성공 기준 구체화
- "잘 되게 해" 대신 검증 가능한 조건 나열
- 테스트 명령어, 예상 결과를 포함

### 5. 범위 한정
- 건드리면 안 되는 파일/영역 명시
- 판단이 필요한 상황이면 "메인에 보고" 지시

## 예시: 나쁜 프롬프트 vs 좋은 프롬프트

### 나쁜 프롬프트
```
어드민 서버 배포해줘
```

### 좋은 프롬프트
```markdown
## 작업 지시서

### 목표
SelfPostingAdmin 서버를 빌드하고 배포한다.

### 맥락
- 프로젝트: selfpost (Spring Boot 멀티모듈)
- 기술 스택: Java 17, Spring Boot 3.x, Gradle
- 빌드 명령어: ./gradlew clean :SelfPostingAdmin:bootJar -x test

### 작업 범위
1. Gradle로 SelfPostingAdmin 모듈 JAR 빌드
2. 포트 5001 사용 중인 프로세스 종료
3. 빌드된 JAR을 `C:/Users/앤기브마케팅/Desktop/관리자서버 시작/App.jar`로 복사
4. `start.bat` 실행하여 서버 시작
5. 12초 대기 후 https://admin.selfposting.kr/login 에 HTTP 200 확인

### 제약 조건
- Windows 환경 (powershell 사용)
- 테스트 스킵 (-x test)

### 성공 기준
- [ ] JAR 빌드 성공 (BUILD SUCCESSFUL)
- [ ] 기존 서버 프로세스 종료 완료
- [ ] App.jar 교체 완료
- [ ] https://admin.selfposting.kr/login HTTP 200 응답

### 하지 말 것
- 소스 코드 수정 금지
- Gradle 설정 변경 금지
```
