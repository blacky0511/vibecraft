# vibecraft 도움말

다음 내용을 사용자에게 보여주세요:

## vibecraft - 바이브코딩 네비게이션

### 자동 감지 모드
작업을 요청하면 자동으로 감지됩니다:
- **새 기능**: "~만들어줘", "~추가해줘", "~해줘", "~필요해"
- **디버깅**: "~에러", "~안 돼", "~버그", "~왜 이래", "~작동 안 해"
- **분석**: "~분석해줘", "~데이터 뽑아", "~통계", "~SQL"
- **단순 수정**: "~키워줘", "~색상 바꿔", "~폰트", "~마진"
- **프로젝트 시작**: "~만들자", "~앱", "~사이트"
- **코드 리뷰**: "~리뷰해줘", "~봐줘", "~검토", "~괜찮은지"
- **배포**: "~배포", "~릴리즈", "~서버에 올려"
- **리서치**: "~리서치해줘", "~조사해줘", "~파악해줘"

### 명령어 (자연어가 안 될 때 직접 사용)

**RPDCA 워크플로우:**
| 명령어 | 용도 |
|--------|------|
| `/feature` | 새 기능 추가 시작 |
| `/research` | 코드베이스 리서치 |
| `/brainstorm` | 아이디어 → 설계 |
| `/plan` | 구현 계획 작성 |
| `/execute` | 계획 실행 |
| `/verify` | 검증 게이트 |
| `/pdca` | RPDCA 상태 확인 |

**기타:**
| 명령어 | 용도 |
|--------|------|
| `/debug` | 체계적 디버깅 |
| `/review` | 코드 리뷰 |
| `/deploy` | 배포 가이드 |
| `/kickoff` | 새 프로젝트 시작 |
| `/analyze` | 데이터/코드 분석 |
| `/simplify` | 코드 정리 |
| `/ralph` | 반복 자동 수정 (테스트/타입/린트 에러 일괄 해결) |
| `/team` | CTO 에이전트팀 |

### 자동 제안
- **에이전트팀**: 여러 레이어 병렬 작업 → "/team으로 해줘"
- **ralph-loop**: 반복 개선형 작업 → "ralph-loop으로 해줘"

### 작업 크기별 워크플로우 (스마트 RPDCA)
- **S (소)**: 파일 1~2개 → 바로 실행 → 검증
- **M (중)**: 파일 3~5개 → 계획 → 실행 → 검증
- **L (대)**: 파일 6개+ → brainstorming → 계획 → 팀 구성 → 병렬 실행 → 리뷰 → 검증

### 철칙 (Iron Law)
1. 테스트 먼저 작성 (TDD)
2. 증거 없이 완료 없다

### 안전 가드 (자동 적용)
- 파일 수정 전: 영향 범위 분석 (PreToolUse 훅)
- 커밋 전: 테스트 실행 여부 확인 (commit-guard)
- 위험한 Git 명령어 감지 시 경고 (git-safety-guard)
- 매 응답 끝: 다음 명령어 리마인더 (Stop 훅)
- 스킬 완료 후: 다음 단계 자동 제안 (PostToolUse 훅)
