# 체계적 디버깅 시작

vibecraft:systematic-debugging 스킬을 호출하여 4단계 디버깅을 진행한다.

## 인자가 없을 때

사용자에게 증상을 물어본다:
- "어떤 에러가 발생하나요?"
- "언제부터 문제가 생겼나요?"
- "최근에 변경한 코드가 있나요?"

## 인자가 있을 때 (에러 메시지/증상)

바로 4단계 디버깅을 시작한다:

### 1단계: 증거 수집
- 에러 메시지 분석
- 관련 로그 확인
- 재현 조건 파악

### 2단계: 가설 수립
- 가능한 원인 3개 이내로 나열
- 각 가설의 근거 제시

### 3단계: 가설 검증
- 가장 유력한 가설부터 검증
- 코드와 로그로 증거 확인
- 추측으로 수정하지 않는다

### 4단계: 최소 수정
- 원인이 확인된 후에만 수정
- 변경 범위를 최소화
- 수정 후 재현 테스트로 해결 확인
