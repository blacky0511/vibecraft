# 영향 범위 분석 (Impact Analysis)

## 역할

코드를 수정하기 전에 "이걸 바꾸면 어디가 영향받는지"를 자동으로 분석한다.

## 활성화 조건

다음 상황에서 자동으로 실행된다:
- 기존 파일을 수정하려 할 때
- 공통 컴포넌트, 유틸 함수를 변경할 때
- API 엔드포인트의 요청/응답 형식을 바꿀 때
- 데이터베이스 스키마를 변경할 때

## 분석 절차

### Step 1: 변경 대상 파일 확인

수정하려는 파일을 먼저 Read로 읽는다.

### Step 2: 역방향 의존성 검색

Grep으로 이 파일/함수/컴포넌트를 **import하거나 사용하는 곳**을 전부 찾는다.

```
검색 패턴:
- import ... from '{대상 파일}'
- require('{대상 파일}')
- <컴포넌트명 으로 사용하는 JSX/TSX
- 함수명()으로 호출하는 곳
```

### Step 3: 영향 수준 판단

| 수준 | 조건 | 행동 |
|------|------|------|
| 안전 | 사용하는 곳 0개 (단독 파일) | 바로 수정 |
| 주의 | 사용하는 곳 1~3개 | 영향 파일 목록 안내 후 수정 |
| 위험 | 사용하는 곳 4개 이상 또는 공통 컴포넌트 | 반드시 사용자 확인 후 수정 |

### Step 4: 안내 메시지

```
📊 영향 범위 분석 결과:

이 파일을 수정하면 영향받는 곳:
- pages/home.tsx:23 (HomeHeader 컴포넌트에서 사용)
- pages/about.tsx:45 (AboutSection에서 사용)
- components/layout.tsx:12 (공통 레이아웃에서 사용)

총 3곳에서 사용 중입니다. 함께 수정할까요?
```

## 수정하지 않는 경우

- 새 파일 생성 (영향받을 곳이 없으므로)
- 파일 내부 로직만 변경하고 외부 인터페이스(Props, 함수 시그니처)는 유지하는 경우
- simple-tweak 모드 (단순 수치 변경)
