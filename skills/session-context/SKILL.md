# 세션 맥락 보존

## 역할

auto-compact로 이전 대화 내용이 압축되어도,
핵심 맥락이 유실되지 않도록 세션 파일로 보존한다.

## 세션 파일

- **위치**: `docs/session.md` (프로젝트 루트 기준)
- **크기**: 최대 30줄 이내 (핵심만 유지)
- **수명**: 작업 시작 ~ 작업 완료까지

## 동작 흐름

### 1. 작업 시작 시 → 세션 파일 생성

새로운 개발 작업이 시작되면 세션 파일을 생성한다.

```markdown
# 현재 세션

## 작업 목표
- (사용자가 요청한 것의 핵심 요약)

## 현재 상태
- 단계: (Plan/Do/Check/Act)
- 진행: (어디까지 했는지)

## 핵심 결정 사항
- (왜 이 방식을 선택했는지)
- (사용자가 확인/승인한 내용)

## 변경된 파일
- (수정한 파일 목록)

## 남은 작업
- (아직 안 한 것)
```

### 2. 주요 단계 완료 시 → 세션 파일 업데이트

다음 타이밍에 세션 파일을 업데이트한다:
- 설계/계획 확정 후
- 파일 생성/수정 완료 후
- 커밋 직전
- 사용자의 중요한 결정 직후

**업데이트 규칙:**
- 전체 내용을 덮어쓴다 (히스토리 누적하지 않음)
- 현재 시점의 스냅샷만 유지한다
- 30줄을 넘지 않도록 요약한다

### 3. compact 발생 후 → 세션 파일 읽기

대화 맥락이 얕아졌다고 느껴지면 (이전 내용을 기억 못할 때):
1. `docs/session.md`를 읽는다
2. 세션 파일 기반으로 맥락을 복구한다
3. 사용자에게 알린다:
   > "세션 파일에서 맥락을 복구했습니다. 이어서 진행할게요."

### 4. 작업 완료 시 → 세션 파일 삭제

작업이 완전히 끝나면 (커밋 완료, 사용자 확인 후):
1. 세션 파일을 삭제한다
2. 필요하면 memory에 장기 기억할 내용만 저장한다

## 세션 파일 작성 규칙

### DO
- 현재 상태의 스냅샷만 유지 (최신 상태)
- 사용자의 결정/승인 내용 기록
- 변경된 파일과 이유 기록
- 남은 작업 목록 유지

### DON'T
- 대화 내용을 통째로 복사하지 않는다
- 코드 전체를 넣지 않는다 (파일명:줄번호로 참조)
- 30줄을 초과하지 않는다
- 임시 디버깅 내용은 넣지 않는다

## .gitignore 처리

세션 파일은 임시 파일이므로, 프로젝트의 `.gitignore`에 추가를 권장한다:
```
docs/session.md
```
처음 세션 파일 생성 시 `.gitignore`에 없으면 사용자에게 추가 여부를 물어본다.
