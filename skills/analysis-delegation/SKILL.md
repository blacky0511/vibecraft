# 분석 작업 자동 위임 스킬

## 역할

분석 작업을 감지하면, **메인 컨텍스트에서 직접 수행하지 않고**
서브에이전트(Task 도구)로 위임하여 컨텍스트를 보호한다.

모든 분석은 **deep-analysis 4단계 방법론**을 따른다.
상세 방법론은 `references/deep-analysis-methodology.md`를 참고한다.
1차 결론에서 멈추지 않고, 교란 변수 탐색 → 코호트 추적 → 인과 검증까지 수행한다.

---

## 왜 서브에이전트로 위임하는가

분석 작업의 특성:
- 스크립트 작성 → 실행 → 에러 → 수정 → 재실행 **반복**이 잦다
- 쿼리 결과가 대량으로 출력된다
- 프로젝트 코드 자체를 변경하는 것이 아니라 **일회용 스크립트**를 쓴다
- 중간 과정보다 **최종 분석 결과**만 중요하다

이 반복 과정이 메인 컨텍스트에 쌓이면 빠르게 소진된다.
서브에이전트 안에서 반복이 일어나면 메인에는 결과 요약만 돌아온다.

---

## 감지 기준

다음 키워드/패턴이 감지되면 분석 모드로 진입한다:

**키워드**: "분석", "분석해줘", "데이터 뽑아", "DB 조회", "쿼리", "로그 분석", "통계", "리포트", "패턴 분석", "추출", "집계", "원인 파악", "수치 확인", "비교해줘", "트렌드", "현황"

**패턴 판별**:
- 프로젝트 코드 변경이 아닌, 데이터를 조회/분석하는 요청
- SQL 쿼리, 로그 파싱, API 호출 등으로 데이터를 수집하는 작업
- 결과를 해석하여 인사이트를 도출하는 작업

**분석이 아닌 경우** (다른 모드로 라우팅):
- "이 함수 분석해줘" → 코드 리뷰 (코드 이해 목적)
- "에러 로그 분석해줘" → 디버깅 (버그 수정 목적)
- "성능 분석해줘" → 상황에 따라 분석 또는 디버깅

## 규모별 분기

분석 작업의 규모를 판단하여 실행 방식을 자동 선택한다.

| 규모 | 조건 | 실행 방식 |
|------|------|----------|
| **S** | 단일 테이블/파일, 간단한 집계, 명확한 질문 | data-analyst 1개 + deep-analysis 4단계 |
| **M** | 여러 테이블/파일, 복잡한 조건, 다중 지표 | data-analyst 1개 + deep-analysis 4단계 + 중간 보고 |
| **L** | 복수 데이터 소스, 복합 분석, 인과 추론 필요 | data-analyst 3개 병렬(관점별) + 결과 종합 |

### 규모 판별 기준

**S (Small)**:
- "이번 달 매출 뽑아줘"
- "오늘 에러 건수 확인해줘"
- 단일 데이터 소스, 단순 집계/조회

**M (Medium)**:
- "월별 매출 추이와 원인 분석해줘"
- "A 테이블과 B 테이블 조인해서 패턴 찾아줘"
- 여러 데이터 소스, 비교 분석 필요

**L (Large)**:
- "누락률의 근본 원인을 찾아줘"
- "전체 시스템의 성능 병목을 분석해줘"
- 복수 데이터 소스, 교란 변수 탐색 + 인과 검증 필수

---

## S 사이즈 실행

### 1단계: 분석 범위 파악

사용자에게 필요한 정보를 확인한다:
- 무엇을 분석할 것인가 (DB, 로그, API 응답 등)
- 어떤 데이터가 필요한가 (기간, 조건, 비교 대상)
- 어떤 결론을 기대하는가 (원인 파악, 개선방안, 현황 보고)

### 2단계: data-analyst 에이전트 실행

```
Task 도구 호출:
- subagent_type: "vibecraft:data-analyst"
- mode: "bypassPermissions"

프롬프트에 포함:
1. 분석 목적과 배경
2. 데이터 접속 정보
3. deep-analysis 4단계를 모두 수행할 것
4. 결과 저장 경로
5. 최종 보고서 형식
```

### 3단계: 결과 수신 및 전달

data-analyst가 반환한 4단계 분석 결과를 사용자에게 정리하여 전달한다.

---

## M 사이즈 실행

S 사이즈와 동일하되, **중간 보고** 절차가 추가된다.

### 추가 절차: 2단계 후 중간 보고

data-analyst가 deep-analysis 2단계(교란 변수 탐색)까지 완료하면,
중간 결과를 사용자에게 보고한다:

```
## 중간 보고 (2단계 완료)

### 1차 가설
- {표면 분석에서 발견한 패턴}

### 교란 변수 발견
- {숨은 변수 목록}

### 분석 방향 제안
- 방향 A: {설명}
- 방향 B: {설명}

어떤 방향으로 3~4단계를 진행할까요?
```

사용자의 방향 선택 후 3~4단계를 계속 진행한다.

---

## L 사이즈 실행: 병렬 관점 분석

대규모 분석에서는 3개의 data-analyst를 **서로 다른 관점**으로 동시 실행한다.

### 관점별 에이전트 구성

| 에이전트 | 관점 | 역할 |
|---------|------|------|
| data-analyst A | 시간 축 | 시계열 분석, 추세, 변화 시점 탐지 |
| data-analyst B | 그룹 축 | 세그먼트 비교, 교란 변수 탐색 |
| data-analyst C | 반증 | A/B의 결론에 대한 반증 시도, 대안 가설 검증 |

### 실행 절차

1. **1차 병렬 실행 (관점 A + B)**
   - data-analyst A: 시간 축으로 deep-analysis 1~3단계 수행
   - data-analyst B: 그룹 축으로 deep-analysis 1~3단계 수행
   - 두 에이전트는 독립적으로 실행된다

2. **중간 종합**
   - A와 B의 결과를 취합한다
   - 사용자에게 중간 보고한다

3. **반증 실행 (관점 C)**
   - data-analyst C: A와 B의 결론을 받아 deep-analysis 4단계(인과 검증) 수행
   - A와 B의 결론에 대한 반례 탐색
   - 대안 가설 수립 및 검증

4. **최종 종합**
   - 3개 에이전트의 결과를 종합하여 최종 보고서 작성

### L 사이즈 프롬프트 예시

```markdown
# 관점 A: 시간 축 분석

## 배경
{분석 배경}

## 데이터 접속
{접속 정보}

## 분석 관점
시간 축 분석에 집중한다:
- 시계열 변화 추적
- 추세, 계절성, 이상값 탐지
- 변화 시점과 관련 이벤트 매칭

## 방법론
deep-analysis 1~3단계를 수행한다:
1단계: 시간 축 기본 통계
2단계: 시간 관련 교란 변수 (수집 방식 변경, 기준 변경 등)
3단계: 코호트별 시간 축 추적

## 결과 저장
{경로}/analysis_time_axis.txt
```

## 서브에이전트 프롬프트 템플릿

### 기본 템플릿 (S/M 사이즈)

```markdown
# {분석 주제} 분석 작업

## 배경
{사용자가 제공한 배경 정보}

## 데이터 접속
{DB 접속 정보 또는 파일 경로}

## 이미 파악된 정보
{스키마, 구조, 이전 분석 결과 등}

## 분석 항목
{번호 매긴 분석 항목 목록}

## 분석 방법론 (필수)
deep-analysis 4단계를 반드시 따른다:
1단계: 표면 분석 - 기본 통계, 1차 가설 기록 (확정 금지)
2단계: 교란 변수 탐색 - 3개 축 교차 분석, 숨은 변수 체크리스트
3단계: 코호트 추적 - 동일 그룹 시간 축 추적
4단계: 인과 검증 - 반증 시도, 대안 가설 검토

## 실행 방법
{스크립트 언어, 실행 환경, 드라이버 경로 등}

## 결과 저장
- 분석 결과: {프로젝트경로}/analysis_result.txt 에 저장

## 최종 결과물
4단계를 모두 거친 후 다음을 정리해서 반환:
1. 핵심 발견사항 (데이터 근거와 함께)
2. 교란 변수 확인 결과
3. 인과 검증 결과 (확신도 포함)
4. 구체적 개선방안 (우선순위 포함)
5. 분석의 한계점
```

```
- {데이터 근거와 함께 발견사항 나열}

- {발견된 교란 변수와 영향}

### 개선방안
| 우선순위 | 방안 | 예상 효과 | 근거 |
|---------|------|----------|------|
| 1 | ... | ... | ... |

### 한계 및 추가 분석
- {이 분석의 한계점}
- {추가로 확인이 필요한 사항}

### 상세 데이터
필요 시 analysis_result.txt 파일 참조
```

---

## 추가 분석 요청 시

사용자가 추가 분석을 요청하면:
- 이전 분석 결과를 컨텍스트에 포함하여 새 서브에이전트를 띄운다
- 이전 결과 파일(analysis_result.txt)을 참조하도록 안내한다
- 매번 새 서브에이전트를 사용하여 메인 컨텍스트를 보호한다

---

## 주의사항

- **프로젝트 코드 변경이 아닌 순수 분석 작업에만 적용**한다
- 분석 결과를 바탕으로 코드를 수정해야 할 때는 분석 완료 후 별도 모드(새 기능/디버깅)로 전환한다
- DB 비밀번호 등 민감 정보는 서브에이전트 프롬프트에 직접 포함한다 (서브에이전트는 격리 환경)
- 서브에이전트 실행 중 사용자에게 진행 상황을 안내한다
- **deep-analysis 4단계를 생략하지 않는다** — 특히 2단계(교란 변수)와 4단계(반증)는 필수
