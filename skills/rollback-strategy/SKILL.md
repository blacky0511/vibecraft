# 롤백 전략 (Rollback Strategy)

## 역할

큰 수정을 하기 전에 되돌릴 준비를 먼저 하고, 문제 생기면 즉시 복구한다.

## 활성화 조건

다음 중 하나라도 해당하면 자동 활성화:
- 수정 파일이 3개 이상
- 공통 컴포넌트/유틸리티 변경
- 데이터베이스 스키마 변경
- 패키지 메이저 버전 업그레이드
- 사용자가 "리팩토링", "마이그레이션" 언급

## 체크포인트 생성

### 작업 전

```bash
# 현재 상태를 커밋 (작업 중인 변경사항이 있으면)
git add -A
git commit -m "[체크포인트] {작업명} 시작 전 상태 저장"
```

사용자에게 안내:
```
🔖 체크포인트를 만들었습니다.
   문제가 생기면 "롤백해줘"라고 말씀하세요.
   이 시점으로 바로 되돌립니다.
```

### 롤백 실행 ("롤백해줘" 감지 시)

1. 사용자에게 확인:
   ```
   마지막 체크포인트로 되돌리면 이후 변경사항이 전부 사라집니다.
   정말 롤백할까요?
   ```

2. 확인 후:
   ```bash
   git reset --hard {체크포인트 커밋 해시}
   ```

3. 결과 안내:
   ```
   ✅ 롤백 완료. 체크포인트 시점으로 되돌아갔습니다.
   다시 시작할까요?
   ```

## 주의사항

- 체크포인트 커밋은 작업 완료 후 squash하거나 정리할 수 있다
- 롤백은 **반드시 사용자 확인 후** 실행한다 (되돌릴 수 없으므로)
- 커밋되지 않은 변경사항이 있으면 먼저 스태시하거나 커밋한다
- simple-tweak 같은 소규모 작업에는 활성화하지 않는다
