# 프리플라이트 체크 (Pre-flight Check)

## 역할

코드를 새로 만들기 전에 "이미 있는 건 없는지, 충돌할 건 없는지" 확인한다.

## 활성화 조건

- 새 함수/컴포넌트/유틸리티를 만들려 할 때
- 새 패키지를 설치하려 할 때
- 새 API 엔드포인트를 추가하려 할 때

## 체크 절차

### 1. 기존 코드 검색

```
검색 대상:
- 같은 이름 또는 비슷한 이름의 함수/컴포넌트
- 같은 기능을 하는 코드 (유사 패턴)
- 이미 설치된 라이브러리 중 해당 기능을 제공하는 것
```

Grep과 Glob으로 프로젝트 전체를 스캔한다.

### 2. 결과에 따른 행동

**이미 있는 경우:**
```
🔍 프리플라이트 체크 결과:

비슷한 기능이 이미 있습니다:
- utils/format.ts:34에 formatDate() 함수가 있습니다
- date-fns 라이브러리가 이미 설치되어 있습니다 (package.json:15)

선택지:
1. 기존 것 활용 (추천)
2. 새로 만들기 (기존과 용도가 다른 경우)
```

**없는 경우:**
```
🔍 프리플라이트 체크 결과:

비슷한 기능이 없습니다. 새로 만들어도 안전합니다.
```

**충돌 가능성이 있는 경우:**
```
🔍 프리플라이트 체크 결과:

⚠️ 주의: 같은 이름의 파일이 이미 있습니다.
- components/Button.tsx (기존)
- 새로 만들려는 Button.tsx와 이름이 충돌합니다.

다른 이름을 사용하거나, 기존 파일을 수정하는 게 나을 수 있습니다.
```

### 3. 패키지 체크

새 패키지 설치가 필요한 경우 → dependency-auditor 스킬이 자동으로 검증한다.

## 스킵 조건

- simple-tweak 모드 (기존 코드 값만 수정)
- 명확히 새로운 영역의 코드 (기존과 겹칠 가능성 없음)
