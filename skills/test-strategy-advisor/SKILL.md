# 테스트 전략 어드바이저 (Test Strategy Advisor)

## 역할

"뭘 테스트해야 하는지"와 "어떤 종류의 테스트를 쓸지"를 가이드한다.

## 테스트 우선순위

### 반드시 테스트 (깨지면 사용자에게 피해)

- 인증/인가 로직 (로그인, 토큰 검증, 권한 확인)
- 결제/금액 계산 로직
- 데이터 CRUD의 핵심 흐름
- API 요청/응답 형식
- 입력값 유효성 검사

### 하면 좋음 (품질 향상)

- 유틸리티 함수의 엣지 케이스
- 에러 처리 분기
- 상태 변경 로직
- 조건부 렌더링

### 안 해도 됨 (과잉 테스트)

- CSS 클래스명, 스타일 값
- 정적 텍스트 내용
- 서드파티 라이브러리 자체 기능
- 단순 getter/setter

## 테스트 종류 선택

| 종류 | 용도 | 예시 |
|------|------|------|
| **단위 테스트** | 함수 하나의 입출력 확인 | `calculateTotal(items)` → 정확한 합계 |
| **통합 테스트** | 여러 모듈이 함께 동작하는지 | API 호출 → DB 저장 → 응답 확인 |
| **E2E 테스트** | 실제 사용자 시나리오 | 로그인 → 상품 선택 → 결제 완료 |

### 추천 비율

```
단위 테스트: 70% (빠르고 많이)
통합 테스트: 20% (핵심 흐름만)
E2E 테스트: 10% (가장 중요한 시나리오만)
```

## 안내 방식

기능 구현 후 테스트를 작성할 때:

```
🧪 테스트 전략 제안:

✅ 꼭 테스트할 것:
- 로그인 성공/실패 분기
- 토큰 만료 시 리다이렉트
- 잘못된 이메일 형식 거부

⚡ 시간 되면:
- 비밀번호 강도 검사
- 소셜 로그인 콜백

❌ 안 해도 되는 것:
- 로그인 버튼 텍스트가 "로그인"인지
- 입력 필드 placeholder 텍스트
```

## iron-law와의 관계

- iron-law: "테스트 없이 코드 머지 금지" (원칙)
- test-strategy-advisor: "이 테스트를 쓰세요" (구체적 가이드)
