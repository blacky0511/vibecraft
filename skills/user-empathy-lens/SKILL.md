# 사용자 시선 체커 (User Empathy Lens)

## 역할

기능이 완성된 후, "이걸 실제로 쓰는 사람은 어떻게 느낄까?"를 점검한다.

## 활성화 조건

- UI 컴포넌트 구현 완료 시
- 사용자 인터랙션이 있는 기능 구현 시 (폼, 버튼, 모달 등)
- 에러 상태, 로딩 상태, 빈 상태 처리 시

## 체크 포인트

### 1. 빈 상태 (Empty State)
- 데이터가 없을 때 뭘 보여주는가?
- "데이터가 없습니다" 만 표시하고 끝인가?
- 다음 행동을 안내하는가? ("첫 번째 항목을 추가해보세요")

### 2. 로딩 상태 (Loading State)
- 로딩 중일 때 사용자가 기다리고 있다는 걸 아는가?
- 스피너, 스켈레톤 등 피드백이 있는가?
- 로딩이 길어지면 안내가 있는가?

### 3. 에러 상태 (Error State)
- 에러가 나면 사용자가 뭘 해야 하는지 아는가?
- 다시 시도 버튼이 있는가?
- 입력한 데이터가 사라지지 않는가?

### 4. 사용자 입력 보존
- 에러 후 폼 데이터가 유지되는가?
- 페이지 새로고침 시 작성 중이던 내용이 날아가지 않는가?

### 5. 접근성
- 키보드만으로 조작 가능한가?
- 스크린리더가 읽을 수 있는가? (aria-label)
- 충분한 색상 대비가 있는가?

## 안내 방식

```
👤 사용자 시선 체크:

기능은 잘 동작하는데, 사용자 입장에서 한 가지 짚어볼게요:

현재: 로그인 실패 시 → 이메일+비밀번호 폼이 전부 초기화됨
문제: 사용자가 이메일을 다시 입력해야 함 (짜증)
제안: 비밀번호만 지우고 이메일은 유지

수정할까요?
```

## 강도 조절

- **폼/인증 관련**: 항상 체크 (사용자 경험에 직접 영향)
- **데이터 표시 관련**: 빈 상태/로딩 상태 체크
- **내부 로직**: 스킵 (사용자가 직접 접하지 않는 부분)
