# vibecraft 사용법 학습 가이드

이 문서는 사용자가 "vibecraft 사용법 알려줘"라고 했을 때 읽어서 안내하는 콘텐츠입니다.
한번에 전부 보여주지 말고, 단계별로 나눠서 안내하세요.

---

## 1단계: 기본 사용법 (5분)

### vibecraft는 뭔가요?

vibecraft는 Claude Code에 설치하는 **바이브코딩 도구**입니다.
하고 싶은 걸 한국어로 말하면, AI가 알아서 적절한 방법으로 처리해줍니다.

### 가장 쉬운 사용법

**그냥 하고 싶은 걸 말하세요.** 명령어를 몰라도 됩니다.

```
"로그인 기능 만들어줘"      → AI가 자동으로 계획부터 세워줌
"이거 에러나는데 고쳐줘"    → AI가 원인부터 분석함
"이 코드 좀 봐줘"          → AI가 코드 리뷰 진행
"배포해줘"                → AI가 배포 체크리스트 안내
```

### 명령어를 쓰면 더 정확합니다

명령어는 `/`로 시작합니다. 자연어보다 **확실하게** 원하는 모드로 진입합니다.

```
/feature 로그인 기능 만들어줘    ← 가장 자주 쓰는 명령어
/debug 로그인 시 404 에러        ← 버그 고칠 때
/review                        ← 코드 리뷰
```

**실습:** 지금 바로 `/vibecraft`를 입력해보세요. 전체 명령어 목록이 나옵니다.

## 2단계: 핵심 명령어 5개 (10분)

### 1. `/feature [설명]` — 기능 추가/수정

가장 많이 쓰는 명령어입니다. AI가 작업 크기를 자동 판단합니다:
- **S (소)**: 바로 코드 작성
- **M (중)**: 리서치 → 계획 → 실행 → 검증
- **L (대)**: 리서치 → 계획 → 팀 구성 → 실행 → 검증

```
/feature 회원가입 페이지 만들어줘
/feature 검색 기능에 필터 추가해줘
/feature 다크모드 지원해줘
```

### 2. `/debug [증상]` — 에러/버그 수정

에러 메시지나 증상을 설명하면 체계적으로 분석합니다.
**추측으로 고치지 않고, 원인부터 확인합니다.**

```
/debug 로그인 버튼 클릭해도 반응 없음
/debug TypeError: Cannot read properties of undefined
/debug 빌드 시 에러 발생
```

### 3. `/review` — 코드 리뷰

현재 변경된 코드를 분석하고 개선점을 찾아줍니다.

```
/review                    ← 전체 변경사항 리뷰
/review src/auth/          ← 특정 폴더만 리뷰
```

### 4. `/research [대상]` — 코드 조사

기존 코드가 어떻게 되어있는지 파악합니다.
새로운 프로젝트에 합류했을 때 유용합니다.

```
/research 이 프로젝트 전체 구조 파악해줘
/research 인증 시스템이 어떻게 되어있어?
```

### 5. `/packet [URL]` — API 패킷 캡처

웹사이트의 숨겨진 API를 찾아냅니다. 크롤링/자동화에 핵심입니다.

```
/packet https://example.com
/packet https://shopping.com/products
```

**실습:** 위 명령어 중 하나를 골라서 실제로 입력해보세요.

## 3단계: 워크플로우 이해하기 (15분)

### RPDCA란?

M/L 크기 작업에서 AI가 자동으로 따르는 절차입니다:

```
R (Research)  → 기존 코드 조사
P (Plan)      → 구현 계획 작성 (+ 자동 리뷰)
D (Do)        → 코드 작성
C (Check)     → 검증 (90% 이상 달성해야 통과)
A (Act)       → 미달 시 자동 수정
```

**사용자가 할 일은 2번뿐입니다:**
1. 리서치 결과 확인 → "좋아, 진행해"
2. 계획 확인 → "좋아, 실행해"

나머지는 AI가 자동으로 진행합니다.

### 작업 크기별 차이

| 입력 | AI 판단 | 진행 방식 |
|------|---------|----------|
| "버튼 색상 바꿔줘" | S (소) | 바로 수정 |
| "검색 기능 추가해줘" | M (중) | 계획 → 실행 → 검증 |
| "결제 시스템 만들어줘" | L (대) | 계획 → 팀 구성 → 병렬 실행 → 검증 |

**실습:** `/feature 검색 기능 추가해줘`를 입력하고 AI가 크기를 어떻게 판단하는지 관찰해보세요.

## 4단계: 고급 기능 (20분)

### 에이전트 팀 (`/team`)

대규모 작업을 여러 에이전트가 동시에 처리합니다.

```
/team 프론트엔드 + 백엔드 동시 작업
```

### 반복 수정 (`/ralph`)

에러가 여러 개일 때 하나씩 자동으로 반복 수정합니다.

```
/ralph npm test 전부 통과시켜
/ralph npx tsc --noEmit 에러 다 잡아
```

### 전체 명령어 표

| 명령어 | 용도 | 예시 |
|--------|------|------|
| `/feature [설명]` | 기능 추가/수정 | `/feature 로그인 만들어줘` |
| `/debug [증상]` | 에러/버그 수정 | `/debug 404 에러` |
| `/research [대상]` | 코드 조사 | `/research 구조 파악해줘` |
| `/plan [설명]` | 구현 계획 | `/plan 결제 시스템` |
| `/execute` | 계획 실행 | `/execute` |
| `/verify` | 검증 | `/verify` |
| `/review` | 코드 리뷰 | `/review` |
| `/deploy` | 배포 | `/deploy` |
| `/simplify [경로]` | 코드 정리 | `/simplify src/` |
| `/packet [URL]` | API 추출 | `/packet https://site.com` |
| `/naver [증상]` | 네이버 진단 | `/naver 블로그 차단됨` |
| `/ralph [명령]` | 반복 수정 | `/ralph npm test` |
| `/team [설명]` | 팀 구성 | `/team 병렬 작업` |
| `/brainstorm [아이디어]` | 설계 | `/brainstorm 쿠폰 시스템` |
| `/kickoff [이름]` | 프로젝트 시작 | `/kickoff 쇼핑몰` |
| `/pdca` | 진행 상태 확인 | `/pdca` |
| `/vibecraft` | 도움말 | `/vibecraft` |

## 안내 방법

- 사용자에게 1~4단계를 **한번에 다 보여주지 않는다**
- "다음 단계 보여줘" 또는 "계속"이라고 하면 다음 단계로 진행
- 각 단계 끝에 **실습 과제**를 포함한다
- 실습을 해보면 자연스럽게 다음 단계가 궁금해지도록 유도한다
