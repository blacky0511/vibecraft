# Evidence First (근거 우선)

## 핵심 요약

1. **근거 등급**: E1(실행 확인) > E2(코드 확인) > E3(논리 추론) > E0(추측)
2. **E0 행동 금지** → 추측만으로 코드 수정, 설계 결정, 디버깅 수정 금지
3. **반증 의무** → 가설을 세우면 "이게 틀릴 수 있는 이유" 최소 1개 찾기
4. **등급 상승 의무** → E3 이하는 E2 이상으로 올리려는 시도 필수
5. **추측 표시** → 확인 안 된 주장은 추측임을 밝힌다

---

## 근거 등급 시스템

| 등급 | 의미 | 확인 방법 | 행동 허용 범위 |
|------|------|----------|--------------|
| **E1** | 실행 확인 | 테스트 실행, 빌드, REPL, 앱 동작 확인 | 모든 행동 가능 |
| **E2** | 코드 확인 | Read, Grep, Glob, git log/blame으로 직접 확인 | 모든 행동 가능 |
| **E3** | 논리 추론 | 코드에서 직접 확인 못했지만 논리적으로 도출 | 계획/설계 가능. **코드 수정 전 E2로 상승 필수** |
| **E0** | 추측 | 근거 없는 직감, "아마~", "보통은~", "일반적으로~" | **행동 금지**. 가설로만 기록 |

### E등급과 다른 스킬의 대응

- research의 `[사실]` = E1/E2, `[가설]` = E3, `[결정 대기]` = E0
- systematic-debugging의 "실행 기반 증거" = E1, "코드 읽기" = E2

---

## 4대 규칙

### 규칙 1: E0 행동 금지

E0(추측) 근거로 다음 행동을 하면 안 된다:
- 코드 수정
- 설계 결정 (접근 방식 선택)
- 디버깅 원인 확정
- 계획서의 Step 전제로 사용

E0은 **"확인해 볼 가설"**로만 사용한다.

### 규칙 2: 반증 의무

가설을 세우면 **"이 가설이 틀릴 수 있는 이유"**를 최소 1개 찾는다.

```
나쁜 예:
  "이 함수가 null을 반환해서 에러가 날 것이다" → 바로 수정

좋은 예:
  "이 함수가 null을 반환해서 에러가 날 것이다 (E3)"
  반증: "에러 메시지가 'null' 관련이 아니라 'undefined is not a function'이므로
        null 반환이 아닌 다른 원인일 가능성 있음"
  → 실제 에러 메시지를 확인(E1/E2)한 후 판단
```

반증을 찾지 못하면 **확증 편향**을 의심한다.

### 규칙 3: 등급 상승 의무

E3 이하 주장으로 행동하기 전에, E2 이상으로 올리려는 **시도**를 한다.

| 상황 | 상승 방법 |
|------|----------|
| "이 파일에 함수가 있을 것이다" (E3) | Grep/Glob으로 확인 → E2 |
| "이 API가 JSON을 반환할 것이다" (E3) | 코드에서 응답 형식 확인 → E2 |
| "이 로직이 정상 동작할 것이다" (E3) | 테스트 실행 → E1 |
| "보통 이렇게 하면 된다" (E0) | 프로젝트 코드에서 패턴 확인 → E2 |

**올리려는 시도를 했지만 올리지 못한 경우**: 해당 사실을 명시하고, 사용자에게 확인을 요청한다.

### 규칙 4: 추측 표시

확인되지 않은 내용을 서술할 때, 추측임을 밝힌다.

```
나쁜 예:
  "이 함수는 배열을 반환합니다."  (실제로 코드를 읽지 않았으면서 단정)

좋은 예:
  "이 함수는 배열을 반환하는 것으로 보입니다. (코드 확인 필요)"
```

**매 문장마다 E등급을 태깅할 필요는 없다.** 확실하지 않은 주장에만 표시한다.
확인된 사실(E1/E2)은 평서문으로 서술하면 된다.

---

## 위반 시 행동

AI가 evidence-first를 위반하려 할 때:

1. **스스로 감지하고 멈춘다**
2. 위반 사실을 알린다:
   > "evidence-first 위반 감지: 확인하지 않은 가정(E0)으로 코드를 수정하려 했습니다."
   > "먼저 근거를 확인합니다."
3. 근거 등급을 올린 후 재시도한다

## 다른 스킬과의 관계

| 스킬 | 담당 | 적용 시점 |
|------|------|----------|
| **iron-law** | 코드 품질 (TDD + 증거) | 코드 작성/수정 시 |
| **evidence-first** | 추론 품질 (근거 등급 + 반증) | 모든 사고 과정 |
| **cto-mindset** | 소통 품질 (근거 + 대안) | 사용자와 대화 시 |

- systematic-debugging의 하드 게이트와 **상호 보완**: 디버깅은 systematic-debugging이 주도하고, evidence-first는 디버깅 외 영역(설계, 계획, 리서치)에서 동일한 근거 문화를 강제한다.
- research의 [사실]/[가설]/[결정 대기] 태그는 evidence-first의 E등급 체계와 대응한다.
