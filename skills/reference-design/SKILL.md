# 레퍼런스 기반 UI 디자인 (reference-design)

## 역할

레퍼런스 기반 UI 구현의 전체 흐름을 가이드하는 스킬.
docs/ux.md 디자인 토큰을 강제 적용하여 일관된 UI를 생성한다.

- **모드 A**: 레퍼런스 URL이 있으면 크롤링 → 토큰 매핑 → 테마 생성
- **모드 B**: URL이 없으면 분위기 선택 → 토큰 기반 테마 생성

frontend-design 플러그인과 보완 관계: 플러그인이 감각(크리에이티브)을 담당하면, 이 스킬은 규율(토큰 일관성, 접근성, 상태 정의)을 담당한다.

---

## 모드 분기

```
사용자 입력 분석
    |
    +-- URL 포함 --> [모드 A] 레퍼런스 크롤링 (5단계)
    |
    +-- URL 없음 --> [모드 B] ux.md 토큰 기반 직접 구현 (4단계)
```

---

## 모드 A: 레퍼런스 있음 (5단계)

### 1단계: 레퍼런스 크롤링

Playwright로 대상 사이트에 접속하여 디자인 구조를 추출한다.

**추출 항목:**
- 색상 팔레트 (배경, 텍스트, 액센트, 보더)
- 폰트 (패밀리, 사이즈, 웨이트)
- 간격 (패딩, 마진, 갭)
- 레이아웃 구조 (그리드, 컬럼 수, max-width)
- 컴포넌트 패턴 (버튼, 카드, 인풋 등의 크기/스타일)

**크롤링 한계 표시:**

아래 항목은 자동 추출이 어려우므로 "수동 확인 필요"로 마킹한다:
- 커스텀 폰트 (웹폰트 URL만 추출, 라이선스는 사용자가 확인)
- 복잡한 애니메이션 시퀀스
- 이미지/일러스트 에셋
- SVG 아이콘 세트

### 2단계: ux.md 토큰 매핑

추출된 값을 가장 가까운 docs/ux.md 디자인 토큰으로 정규화한다.

**매핑 규칙:**
- 간격: 추출값 → 가장 가까운 8pt grid 값 (예: 15px → space-md 16px, 11px → space-sm 12px)
- 폰트 크기: 추출값 → 가장 가까운 타이포그래피 스케일 (예: 15px → body 16px)
- border-radius: 추출값 → 가장 가까운 radius 토큰 (예: 6px → radius-sm 4px 또는 radius-md 8px)
- 색상: 추출값을 그대로 사용하되, 대비율 검증 수행

**테마 JSON 생성:**

CLAUDE.md 5-4 구조를 따라 테마 JSON을 생성한다:

```json
{
  "themeName": "레퍼런스 사이트명 기반 테마",
  "colorScheme": "dark | light",
  "colors": {
    "background": { "primary": "", "secondary": "", "tertiary": "" },
    "text": { "primary": "", "secondary": "", "muted": "" },
    "accent": { "primary": "", "hover": "" },
    "border": "",
    "status": { "success": "", "warning": "", "error": "", "info": "" }
  },
  "typography": {
    "fontFamily": { "display": "", "body": "", "mono": "" },
    "fontSize": { "xs": "", "sm": "", "base": "", "lg": "", "xl": "", "2xl": "", "3xl": "" }
  },
  "spacing": { "borderRadius": "", "padding": "", "gap": "" },
  "effects": { "shadow": "", "blur": "", "border": "" },
  "components": {
    "button": { "primary": {}, "secondary": {}, "ghost": {} },
    "card": {},
    "input": {},
    "badge": {}
  }
}
```

### 3단계: 저작권 경계선 적용

레퍼런스에서 가져가는 것과 가져가지 않는 것을 명확히 구분한다.

```
가져가는 것 (구조적 패턴)       가져가지 않는 것 (창작물)
-----------------------------  ----------------------------
 레이아웃 구조 (그리드)          로고/브랜드 에셋
 색상 팔레트 비율                일러스트/사진
 타이포그래피 스케일              카피라이팅
 컴포넌트 크기/간격              아이콘 세트
 인터랙션 패턴                   특수 애니메이션 시퀀스
```

사용자에게 이 경계를 명시적으로 안내한다.

### 4단계: 애니메이션 추천

레퍼런스 사이트의 전체적인 분위기를 분석하여 어울리는 애니메이션을 추천한다.

**분위기별 추천 매핑:**

| 분위기 | 추천 애니메이션 | 예시 |
|--------|---------------|------|
| 미니멀/클린 | 부드러운 fade-in, 작은 slide-up | opacity 0->1, translateY(20px->0) |
| 에너지/다이나믹 | staggered reveal, 스케일 인 | 순차 등장, scale(0.9->1) |
| 고급/럭셔리 | 느린 parallax, 텍스트 마스크 | background-attachment: fixed |
| 테크/모던 | 글리치, 카운트업, 타이핑 효과 | 숫자 애니메이션, typewriter |
| 따뜻한/친근한 | 바운스, 부드러운 float | ease-out bounce, gentle bob |
| 대담한/브루탈 | 하드컷, 즉시 등장, 큰 스케일 전환 | 트랜지션 없는 sharp reveal |

**모션 규칙 (ux.md 준수):**
- 호버 효과: 150ms
- 모달/드롭다운 열기: 200ms
- 모달/드롭다운 닫기: 150ms
- 300ms 초과 애니메이션 지양
- `prefers-reduced-motion` 미디어 쿼리 필수

### 5단계: 테마 확정 + 구현 전환

사용자에게 아래를 제시한다:
1. 테마 JSON (2단계 결과)
2. 저작권 경계 요약 (3단계 결과)
3. 애니메이션 추천 (4단계 결과)

사용자가 확인/수정 후, 작업 크기에 따라:
- **S**: 직접 구현
- **M**: writing-plans로 계획 후 구현
- **L**: writing-plans → team-orchestration으로 병렬 구현

## 모드 B: 레퍼런스 없음 (4단계)

### 1단계: 분위기 질문

사용자에게 원하는 UI 분위기를 물어본다:

```
어떤 느낌의 UI를 원하세요?

1. 미니멀/클린 - 여백 많고 깔끔한 느낌
2. 대담한/임팩트 - 큰 타이포, 강한 대비
3. 따뜻한/친근한 - 둥근 모서리, 부드러운 색상
4. 고급/프리미엄 - 어두운 배경, 세련된 디테일
5. 기타 (직접 설명)
```

### 2단계: ux.md 토큰 기반 테마 생성

선택된 분위기에 맞는 색상/폰트/간격을 docs/ux.md 토큰 범위 내에서 조합한다.

**분위기별 토큰 조합 가이드:**

| 분위기 | 색상 경향 | 폰트 경향 | 간격 경향 | border-radius |
|--------|----------|----------|----------|---------------|
| 미니멀/클린 | 무채색 + 단일 액센트 | 얇은 산세리프 | 넉넉 (space-lg~xl) | radius-sm~md |
| 대담한/임팩트 | 고대비 (흑백 + 비비드 액센트) | 굵은 디스플레이 | 타이트~보통 | radius-sm 또는 0 |
| 따뜻한/친근한 | 난색 계열 (오렌지, 코랄) | 둥글둥글한 산세리프 | 보통 (space-md) | radius-lg~xl |
| 고급/프리미엄 | 다크 배경 + 골드/실버 액센트 | 세리프 또는 가는 산세리프 | 넉넉 (space-xl~2xl) | radius-sm~md |

CLAUDE.md 5-4 구조의 테마 JSON을 생성한다.

### 3단계: 애니메이션 추천

모드 A의 4단계와 동일한 분위기별 매핑을 사용한다.

### 4단계: 테마 확정 + 구현 전환

모드 A의 5단계와 동일하게 사용자에게 테마 JSON + 애니메이션 추천을 제시하고,
확인 후 구현으로 전환한다.

## 공통: 디자인 품질 체크리스트 (HARD-GATE)

구현 완료 전 반드시 확인한다. docs/ux.md 기준.
하나라도 미충족이면 "완료"를 선언할 수 없다.

```
[ ] 8pt grid 준수 (모든 간격이 4/8의 배수)
[ ] 타이포그래피 스케일 준수 (12px 미만 없음)
[ ] 색상 대비율 (본문 4.5:1, 대형 텍스트 3:1)
[ ] 인터랙티브 상태 5종 정의 (default/hover/focus/active/disabled)
[ ] 포커스 링 (:focus-visible) 존재
[ ] 빈 상태 디자인 존재
[ ] 로딩 상태 디자인 존재 (스켈레톤 또는 스피너)
[ ] 터치 타겟 최소 44x44px
[ ] prefers-reduced-motion 미디어 쿼리 존재
[ ] 시맨틱 HTML (button, a, ul, table 올바르게 사용)
[ ] 카피라이팅은 placeholder로 표시 ("여기에 제목 입력" 등)
[ ] 빈 상태(empty state) 디자인에 다음 행동 안내 포함
[ ] 에러 발생 시 사용자 입력 데이터 유지 (폼 초기화 금지)
[ ] 에러 메시지에 해결 방법 안내 포함 (What + Why + How)
```
