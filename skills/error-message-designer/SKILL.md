# 에러 메시지 디자이너 (Error Message Designer)

## 역할

에러 처리 코드를 작성할 때, 사용자가 이해할 수 있는 메시지를 설계한다.

## 에러 메시지 3원칙

모든 사용자용 에러 메시지는 다음 3가지를 포함해야 한다:

1. **무슨 문제인지** (What): "서버에 연결할 수 없습니다"
2. **왜 발생했을 가능성** (Why): "인터넷 연결이 불안정할 수 있습니다"
3. **어떻게 해결하는지** (How): "잠시 후 다시 시도해주세요"

## 적용 방식

### 코드 작성 시

```typescript
try {
  const data = await fetchUsers();
} catch (error) {
  // 개발자용 로그 (콘솔에만 출력, 사용자에게 안 보임)
  console.error('[fetchUsers 실패]', error);

  // 사용자용 메시지 (화면에 표시됨)
  showError('사용자 목록을 불러올 수 없습니다. 잠시 후 다시 시도해주세요.');
}
```

### BAD 예시 (피해야 할 것)

```
// 기술 용어 노출
"ECONNREFUSED 127.0.0.1:3000"

// 아무 정보 없음
"에러가 발생했습니다"

// 사용자 탓
"잘못된 입력입니다"
```

### GOOD 예시

```
// 구체적이고 친절함
"이메일 형식이 올바르지 않습니다. example@email.com 형태로 입력해주세요."

// 원인과 해결책 제시
"서버 응답이 느립니다. 네트워크 상태를 확인하고 다시 시도해주세요."

// 다음 행동 안내
"로그인이 만료되었습니다. 다시 로그인해주세요."
```

## 활성화 조건

- try-catch 블록을 작성할 때
- API 호출 에러 처리를 구현할 때
- 폼 유효성 검사 메시지를 작성할 때
- 사용자에게 보여지는 에러 상황 전반
