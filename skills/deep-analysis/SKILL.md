# 심층 분석 방법론

## 역할

데이터 분석 시 **표면적 패턴에서 멈추지 않고**, 교란 변수 → 코호트 추적 → 인과 검증까지
자동으로 수행하도록 강제하는 4단계 사고 체크리스트.

systematic-debugging이 "버그의 원인을 증거로 찾는 방법"이라면,
deep-analysis는 "데이터의 진짜 원인을 증거로 찾는 방법"이다.

---

## 왜 필요한가

AI가 데이터 분석에서 흔히 빠지는 함정:

1. **1차 패턴에 만족**: 시간대별 분포만 보고 결론을 내린다
2. **교란 변수 무시**: 비교 그룹의 조건이 다른데 같다고 가정한다
3. **상관 = 인과 오류**: 함께 변하는 것을 원인이라고 단정한다
4. **반증 시도 안 함**: 자기 결론을 뒤집을 데이터를 찾지 않는다

**실제 사례**: 누락률 분석에서 1차 표면 분석(시간대별)으로 잘못된 결론을 내린 뒤,
사용자 힌트 2번을 받고서야 교란 변수(배치/일일 발행량)를 발견함.

→ 이 스킬이 있으면 2단계에서 자동으로 교란 변수를 탐색했을 것이다.

---

## 4단계 분석 프로세스

### 1단계 — 표면 분석

> **목표**: 기본 분포와 통계를 확인하고, 첫 인상을 기록한다.

수행 항목:
- 전체 데이터 규모 파악 (건수, 기간, 범위)
- 기본 통계량 확인 (평균, 중앙값, 분산, 분포 형태)
- 눈에 띄는 패턴 기록 (증가/감소 추세, 이상값, 계절성)
- **첫 인상을 "가설"로 명시적 기록** (나중에 검증 대상)

**핵심 규칙:**
- 이 단계의 결론은 **가설일 뿐**이다. 확정하지 않는다.
- "~인 것 같다" → "가설 1: ~일 수 있다. 검증 필요." 형식으로 기록한다.

```
## 1단계 결과

### 기본 통계
- 데이터 규모: {건수} / {기간}
- 핵심 수치: {평균, 중앙값 등}

### 관찰된 패턴
- 패턴 1: {설명}
- 패턴 2: {설명}

### 1차 가설 (검증 필요)
- 가설 A: {설명} → 2단계에서 검증
- 가설 B: {설명} → 2단계에서 검증
```

---

### 2단계 — 교란 변수 탐색 (핵심)

> **목표**: "이 패턴을 만드는 숨은 변수는?" 을 반드시 질문한다.

이 단계가 가장 중요하다. 1단계에서 발견한 패턴이 **진짜 원인**인지,
아니면 **숨은 변수가 만든 착각**인지 확인한다.

수행 항목:

1. **비교 그룹 동질성 확인**
   - "A와 B를 비교하고 있는데, A와 B의 조건이 정말 같은가?"
   - 양이 다르지 않은가? 시기가 다르지 않은가? 구성이 다르지 않은가?

2. **최소 3개 축 교차 분석**
   - 시간 축: 시간대별, 일별, 주별, 월별
   - 그룹 축: 카테고리별, 유형별, 소스별
   - 조건 축: 크기별, 빈도별, 상태별

3. **숨은 변수 체크리스트**
   - [ ] 데이터 수집 방식이 기간에 따라 달라지지 않았는가?
   - [ ] 비교 대상의 모집단 크기가 다르지 않은가?
   - [ ] 외부 이벤트(배포, 정책 변경, 시즌)가 영향을 주지 않았는가?
   - [ ] 표본 선택 편향이 없는가? (살아남은 것만 보고 있지 않은가?)
   - [ ] 측정 단위/기준이 일관적인가?

4. **심슨의 역설 확인**
   - 전체에서 보이는 패턴이 하위 그룹에서도 동일한가?
   - 하위 그룹별로 쪼개면 반대 패턴이 나타나지 않는가?

**금지 사항:**
- 1단계 가설을 검증 없이 확정하는 것
- 교란 변수가 "없다"고 가정하는 것 (반드시 찾아봐야 한다)

```
## 2단계 결과

### 교차 분석
| 축 | 분석 내용 | 발견 |
|----|---------|------|
| 시간 | {설명} | {결과} |
| 그룹 | {설명} | {결과} |
| 조건 | {설명} | {결과} |

### 교란 변수 확인
- [ ] 비교 그룹 동질성: {결과}
- [ ] 모집단 크기 차이: {결과}
- [ ] 외부 이벤트 영향: {결과}
- [ ] 표본 선택 편향: {결과}
- [ ] 측정 기준 일관성: {결과}

### 가설 업데이트
- 가설 A: {유지/수정/기각} - 근거: {설명}
- 가설 B: {유지/수정/기각} - 근거: {설명}
- 새 가설 C: {2단계에서 발견된 새 가설}
```

---

### 3단계 — 코호트 추적

> **목표**: 동일 그룹을 시간 축으로 추적하여 변화 시점과 원인을 확인한다.

수행 항목:

1. **동일 코호트 정의**
   - 같은 조건을 가진 그룹을 식별한다
   - "같은 시기에 생성된 것", "같은 유형인 것" 등

2. **시간 축 추적**
   - 코호트별로 시간에 따른 변화를 추적한다
   - 변화 시점(전환점)을 정확히 찾는다

3. **이벤트 매칭**
   - 변화 시점에 무슨 일이 있었는지 확인한다
   - 배포, 설정 변경, 외부 이벤트, 데이터 소스 변경 등

4. **코호트 간 비교**
   - 서로 다른 코호트의 패턴을 비교한다
   - 코호트마다 다르게 나타나는 패턴이 있는지 확인한다

```
## 3단계 결과

### 코호트 정의
- 코호트 1: {정의} (N={건수})
- 코호트 2: {정의} (N={건수})

### 시간 축 변화
| 시점 | 코호트 1 | 코호트 2 | 이벤트 |
|------|---------|---------|--------|
| {날짜} | {수치} | {수치} | {이벤트 또는 없음} |

### 변화 시점 분석
- 전환점: {시점} - {변화 내용}
- 관련 이벤트: {설명}
```

---

### 4단계 — 인과 검증 (반증 시도)

> **목표**: 결론을 확정하기 전에, 틀렸을 가능성을 적극적으로 탐색한다.

이 단계를 건너뛰면 안 된다. **자기 결론을 뒤집으려고 노력**해야 한다.

수행 항목:

1. **변수 하나만 다른 그룹 비교**
   - 원인이라고 생각하는 변수 하나만 다르고, 나머지는 동일한 그룹을 찾는다
   - 그 변수가 진짜 원인이면, 이 그룹에서 다른 결과가 나와야 한다

2. **반증 질문**
   - "내 결론이 틀렸다면, 어떤 데이터가 보여야 하는가?"
   - 그 데이터를 실제로 찾아본다
   - 반례가 발견되면 결론을 수정한다

3. **대안 설명 검토**
   - 같은 데이터를 다르게 설명할 수 있는 가설이 있는가?
   - 그 대안 가설을 기각할 증거가 있는가?

4. **결론 확정 기준**
   - 반례가 없거나, 반례를 합리적으로 설명할 수 있을 때만 확정
   - 확신도를 명시한다 (높음/중간/낮음)

**금지 사항:**
- 반증을 시도하지 않고 결론을 확정하는 것
- "아마 이게 원인일 거야"로 끝내는 것
- 반례를 무시하거나 축소하는 것

```
## 4단계 결과

### 인과 검증
| 검증 방법 | 예상 결과 | 실제 결과 | 판정 |
|---------|---------|---------|------|
| {변수 비교} | {예상} | {실제} | 지지/기각 |
| {반증 시도} | {예상} | {실제} | 지지/기각 |

### 대안 가설 검토
| 대안 가설 | 기각 증거 | 판정 |
|---------|---------|------|
| {가설} | {증거} | 기각/미기각 |

### 최종 결론
- 결론: {확정된 결론}
- 확신도: 높음/중간/낮음
- 근거 요약: {핵심 증거 나열}
- 한계: {이 분석의 한계점}
```

---

## 핵심 규칙

- **1단계에서 결론을 내리지 않는다.** 첫 인상은 가설일 뿐이다.
- **2단계를 건너뛰지 않는다.** 교란 변수 탐색은 필수다.
- **4단계에서 반증을 시도한다.** 내 결론이 틀렸을 가능성을 적극 탐색한다.
- "아마 이거일 거야"는 금지. **데이터로 확인한다.**
- 확신도를 항상 명시한다. 100% 확신이 아니면 한계를 밝힌다.

```
- 발견 2: {데이터 근거와 함께}

### 원인 분석
- 1차 가설: {표면 분석 결과}
- 교란 변수: {발견된 교란 변수}

- 확신도: {높음/중간/낮음}

### 교차 검증 결과

### 한계 및 추가 분석 필요 사항

- {추가로 확인이 필요한 사항}
```
