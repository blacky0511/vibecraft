# 체계적 디버깅

## 역할

에러나 버그가 발생했을 때, 추측 없이 4단계 절차를 따라 원인을 찾고 수정한다.

---

## 4단계 디버깅 프로세스

### 1단계 — 증상 수집

> **목표**: 문제가 무엇인지 정확히 파악한다.

아래 항목을 사용자에게 물어서 정보를 확보한다:

- 어떤 에러 메시지가 나오나요? (전체 텍스트 복사 요청)
- 언제부터 발생했나요? (어떤 작업 후부터인지)
- 어떤 환경에서 발생하나요? (로컬/서버, OS, 브라우저 등)
- 항상 발생하나요, 아니면 특정 조건에서만 발생하나요?
- 에러 발생 직전에 어떤 행동을 했나요?

수집 항목:
- [ ] 에러 메시지 전문
- [ ] 스택트레이스 (있을 경우)
- [ ] 재현 조건
- [ ] 최근 변경 사항

---

### 2단계 — 원인 추적

> **목표**: 에러가 코드의 어느 지점에서 발생하는지 확인한다.

다음 순서로 추적한다:

1. **스택트레이스 분석**: 에러가 발생한 파일과 줄 번호를 확인한다.
2. **코드 흐름 추적**: 에러 발생 지점까지 실행 흐름을 역으로 따라간다.
3. **정상 케이스와 비교**: 작동하는 경우와 그렇지 않은 경우의 차이를 찾는다.
4. **최근 변경 사항 확인**: `git diff` 또는 최근 수정된 파일을 검토한다.
5. **로그 추가**: 필요하면 중간 값을 출력하는 임시 로그를 추가해 변수 상태를 확인한다.

---

### 3단계 — 가설 검증

> **목표**: 원인 후보를 좁히고 증거로 확인한다.

1. 관찰된 증거를 바탕으로 원인 가설을 작성한다.
2. 각 가설에 대해 "이게 맞다면 어떤 증거가 있어야 하는가?"를 정의한다.
3. 실제로 그 증거가 있는지 확인한다.
4. 증거가 없으면 가설을 기각하고 다음 가설로 넘어간다.

**가설 검증 표 예시:**

| # | 가설 | 예상 증거 | 실제 확인 | 결론 |
|---|------|-----------|----------|------|
| 1 | API 응답이 null | res.data가 null | 로그 확인 | 확인됨 / 기각됨 |
| 2 | 환경변수 누락 | .env 키 없음 | 파일 확인 | 확인됨 / 기각됨 |

**금지 사항:**
- "아마 이거일 거야"로 바로 코드를 수정하는 것
- 여러 가설을 동시에 검증하는 것 (한 번에 하나씩)

---

### 4단계 — 수정 + 정리 + 검증

> **목표**: 증거로 확인된 원인만 수정하고, 디버깅 잔해를 정리한 뒤 검증한다.

수정 원칙:

1. **최소한의 수정**: 문제 해결에 필요한 것만 바꾼다. 관련 없는 코드는 건드리지 않는다.
2. **한 번에 하나만 변경**: 여러 가지를 동시에 바꾸면 어느 것이 해결했는지 알 수 없다.
3. **수정 전 백업**: 수정 전 코드를 주석 또는 git stash로 보존한다.
4. **code-simplifier 실행**: 수정 완료 후 `code-simplifier` 에이전트를 호출하여 디버깅 잔해(임시 로그, 주석 처리된 코드, 불필요한 변수 등)를 자동 정리한다.
5. **수정 후 검증 필수**: `vibecraft:verification` 스킬을 호출하여 검증한다.

---

## 핵심 규칙

- 추측으로 수정하지 않는다. **반드시 원인을 먼저 확인한다.**
- 한 번에 하나만 변경한다. 여러 개를 동시에 바꾸면 무엇이 고쳐졌는지 알 수 없다.
- "아마 이거일 거야"는 금지. **증거로 확인한다.**
- 수정 후 `code-simplifier`로 디버깅 잔해를 정리한다 (임시 로그, 주석 코드 등).
- 정리 후 반드시 `vibecraft:verification` 스킬로 검증한다.
- iron-law 원칙을 따른다: 테스트 먼저, 증거 필수.

## 디버깅 보고서 템플릿

작업 완료 후 아래 형식으로 보고서를 작성한다.

```
## 디버깅 보고서

### 증상
- 발생 시점:
- 에러 메시지:
- 재현 조건:

### 원인
- 추적 경로:
- 확인된 원인:
- 근거 (증거):

### 수정 내용
- 수정 파일:
- 수정 내용 요약:
- 변경 전 코드:
- 변경 후 코드:

### 검증 결과
- 테스트 실행 결과:
- 동작 확인:
- 결론: 해결됨 / 미해결 (이유)
```

## 재현이 안 되는 버그 대처법

1. 로그를 추가하고 사용자에게 다시 재현을 요청한다.
2. 간헐적 버그라면 조건을 더 좁히도록 질문한다.
3. 최근 배포나 의존성 변경 이력을 확인한다.
4. 임시 방어 코드를 추가하고 원인 파악을 병행한다.
