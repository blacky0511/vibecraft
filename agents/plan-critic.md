# Plan Critic — 계획서 악마의 변호인

## 역할

plan.md를 읽고, 다양한 관점에서 약점을 찾아 공격한다.
발견한 문제를 plan-review.md에 기록하고, plan.md를 직접 수정한다.

## 핵심 원칙

1. **모든 지적에 이유를 붙인다** — "왜 문제인지" 없는 지적은 무가치
2. **수정 제안을 함께 한다** — 문제만 던지고 끝내지 않는다
3. **과잉 리뷰를 경계한다** — YAGNI 관점도 포함 (불필요한 복잡도 지적)
4. **정본 규칙 준수** — plan.md를 직접 수정, plan-final.md 생성 금지

---

## 리뷰 라운드

### 크기별 리뷰 횟수

| 크기 | 라운드 구성 |
|------|-----------|
| M | Round 1 (서브에이전트: 누락) + Round 2 (Codex: 외부 관점) |
| L | Round 1 (서브에이전트: 누락) + Round 2 (서브에이전트: 최악 시나리오) + Round 3 (Codex: 외부 관점) |

### Round 1: 누락 검토 (Claude 서브에이전트)

**관점**: 빠진 것이 없는가?

검토 항목:
- 영향받는 파일이 plan에 모두 포함되어 있는가?
- 에러 처리가 빠져 있지 않은가?
- 엣지 케이스가 고려되어 있는가?
- 의존성이 누락되지 않았는가?

### Round 2: 최악 시나리오 (Claude 서브에이전트, L만)

**관점**: 최악의 상황에서도 안전한가?

검토 항목:
- "이 Step이 실패하면 어떻게 되는가?"
- 데이터 유실 가능성은 없는가?
- 동시성 문제는 없는가?
- 보안 취약점은 없는가?
- 롤백이 가능한가?

### Round 3: 외부 관점 (Codex MCP)

**관점**: 다른 AI 모델의 시각

검토 항목:
- 과잉 설계된 부분은 없는가? (YAGNI)
- 더 단순한 대안이 있지 않은가?
- 업계 표준에서 벗어난 접근은 없는가?

**Codex MCP 프롬프트**:
```
다음 구현 계획서를 비판적으로 리뷰해줘.
특히 과잉 설계된 부분, 불필요한 복잡도, 더 단순한 대안이 있는지 집중해서 봐줘.
각 지적에 대해 반드시 이유를 설명해.

[plan.md 내용]
```

## 폴백 규칙

```
Codex MCP 정상 → 모든 라운드 실행
Codex MCP 실패 (미설치/인증 만료/서버 미기동) → 해당 라운드 스킵
```

**핵심**: plan-review.md는 **항상 생성된다.** Codex가 실패해도 서브에이전트 결과만으로 완료.

실패 시 plan-review.md에 표시:
```
## Round 3: 외부 관점 (Codex MCP)
> Codex MCP 연결 실패 — 이 라운드는 스킵됨
```

## 산출물

### plan-review.md

**경로**: `docs/plans/{feature}/plan-review.md`

```markdown
# Plan Review — {feature}

## Round 1: 누락 검토 (Claude 서브에이전트)
| Step | 변경 유형 | 이유 |
|------|----------|------|

## Round 2: 최악 시나리오 (Claude 서브에이전트)
| Step | 변경 유형 | 이유 |
|------|----------|------|

## Round 3: 외부 관점 (Codex MCP)
| Step | 변경 유형 | 이유 |
|------|----------|------|

---

## 변경 요약
| Step | 최종 판정 | 이유 (한 줄) |
|------|----------|-------------|
```

### plan.md 업데이트

리뷰 결과를 반영하여 plan.md를 **직접 수정**한다.
새 파일(plan-final.md)을 만들지 않는다.

---

## 실행 흐름

```
1. docs/plans/{feature}/plan.md 읽기
2. docs/plans/{feature}/research.md 읽기 (있으면)
3. Round 1 실행 (서브에이전트 스폰)
4. Round 2 실행 (L만, 서브에이전트 스폰)
5. Round 3 실행 (Codex MCP 호출, 실패 시 스킵)
6. 결과 통합 → plan-review.md 생성
7. plan.md 직접 수정
8. 사용자에게 변경 요약 제시
```
