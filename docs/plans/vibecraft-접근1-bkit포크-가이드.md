# vibecraft 접근 1: bkit 포크 + superpowers 이식

## 한 줄 요약
> bkit 플러그인을 복사해서, 안 쓰는 것(bkend.ai)을 빼고, superpowers의 좋은 규칙들을 넣는 방식

---

## 어떤 느낌인가요?

**비유하자면:** 잘 지어진 아파트를 구매해서, 안 쓰는 방을 리모델링하고, 옆집의 좋은 인테리어를 가져오는 것

- bkit이라는 **이미 완성된 플러그인**을 그대로 가져옵니다
- 안 쓰는 bkend.ai 관련 기능 5개를 삭제합니다
- superpowers의 핵심 규칙(테스트 먼저, 검증 후 완료 등)을 추가합니다
- 모든 텍스트를 한국어로 바꿉니다

---

## 최종 결과물 구성

| 구성 요소 | 개수 | 설명 |
|----------|------|------|
| 스킬 | ~25개 | bkit 21개(bkend 5개 제거) + superpowers 4개 추가 |
| 에이전트 | ~15개 | bkit 15개(bkend-expert 제거) + 유지 |
| 훅 스크립트 | ~40개 | bkit 훅 거의 그대로 + superpowers verification 훅 추가 |
| 템플릿 | ~25개 | bkit 템플릿 유지 (bkend 관련만 제거) |
| Output Styles | 4개 | bkit 그대로 유지 |

## 사용 예시 (이렇게 동작합니다)

### 예시 1: 새 기능 개발
```
나: "네이버 계정 비밀번호 일괄 변경 기능 추가해줘"

vibecraft가 하는 일:
1. [brainstorming] 기능에 대해 질문 → 설계 확정
2. [PDCA Plan] 계획서 자동 생성 (한국어 템플릿)
3. [PDCA Design] 설계서 자동 생성
4. [PDCA Do] CTO 에이전트가 팀 구성 → 병렬 개발
   - frontend-architect: 어드민 페이지 UI
   - code-analyzer: 기존 코드 분석
   - security-architect: 보안 검토
5. [Iron Law] 테스트 먼저 작성 → 코드 구현 → 검증
6. [PDCA Check] 설계 대비 90% 이상 달성 확인
7. [PDCA Act] 미달 시 자동 재작업
```

### 예시 2: 버그 수정
```
나: "포스팅 중 Chrome 크래시 발생해"

vibecraft가 하는 일:
1. [systematic-debugging] 4단계 체계적 디버깅
   - Root Cause: 로그 분석, 에러 추적
   - Pattern: 작동하는 경우와 비교
   - Hypothesis: 가설 세우고 검증
   - Implementation: 수정 후 테스트
2. [verification] "고쳤다"고 말하기 전에 반드시 검증 증거 제시
```

### 예시 3: 코드 리뷰
```
나: "이 코드 리뷰해줘"

vibecraft가 하는 일:
1. [code-review] 코드 품질 분석
2. [receiving-code-review] 감정적 반응 없이 기술적 검증
3. [gap-detector] 설계서와 비교해서 빠진 부분 찾기
```

## 장점

1. **빠른 완성**: bkit의 완성된 코드를 재활용하므로 개발 시간 최소
2. **검증된 인프라**: 훅/팀/템플릿 시스템이 이미 안정적으로 동작
3. **풍부한 자동화**: 45개 훅 스크립트가 거의 모든 시나리오 커버
4. **팀 오케스트레이션**: CTO 에이전트의 16개 전문가 팀 운영

## 단점

1. **유지보수 부담**: bkit 원본이 업데이트되면 따라가기 어려움
2. **불필요한 코드**: bkit의 다국어 지원, 복잡한 lib/ 등 안 쓰는 코드가 남을 수 있음
3. **학습 곡선**: bkit의 241개 함수를 이해해야 커스터마이징 가능
4. **bkit 라이선스 의존**: Apache-2.0 라이선스 조건 준수 필요

| 훅 스크립트 수정 | ⭐⭐ 보통 | 기존 훅에 superpowers 규칙 반영 |
| 테스트 | ⭐⭐ 보통 | 기존 jest 테스트 수정 + 새 스킬 테스트 |

**총 예상 작업**: 중간 규모 (기존 코드 활용도 높음)
