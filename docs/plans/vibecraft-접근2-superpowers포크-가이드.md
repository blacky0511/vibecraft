# vibecraft 접근 2: superpowers 포크 + bkit 기능 이식

## 한 줄 요약
> superpowers의 깔끔한 뼈대 위에, bkit의 PDCA/팀/템플릿/훅을 새로 만들어 올리는 방식

---

## 어떤 느낌인가요?

**비유하자면:** 깔끔한 원룸에서 시작해서, 방을 하나씩 증축하며 대저택으로 키우는 것

- superpowers라는 **가볍지만 강력한 플러그인**을 기반으로 시작합니다
- bkit의 PDCA 방법론, CTO 팀 시스템, 템플릿 엔진을 새로 구현합니다
- superpowers의 Iron Law 규칙들은 이미 있으므로 그대로 유지합니다
- 한국어로 처음부터 작성합니다

---

## 최종 결과물 구성

| 구성 요소 | 개수 | 설명 |
|----------|------|------|
| 스킬 | ~25개 | superpowers 14개 유지 + PDCA/파이프라인 11개 새로 작성 |
| 에이전트 | ~15개 | superpowers 1개 + 14개 새로 작성 |
| 훅 스크립트 | ~15개 | superpowers 1개 + 14개 새로 작성 |
| 템플릿 | ~25개 | 전체 새로 작성 |
| Output Styles | 4개 | 새로 작성 |
| lib/ | ~10개 | PDCA/팀/템플릿 엔진 새로 작성 |

---

## 사용 예시 (접근 1과 동일하게 동작)

### 예시 1: 새 기능 개발
```
나: "네이버 계정 비밀번호 일괄 변경 기능 추가해줘"

vibecraft가 하는 일:
(접근 1과 동일한 PDCA + Iron Law + 팀 플로우)
```

**차이점**: 겉으로 보이는 동작은 같지만, 내부 코드가 처음부터 한국어/본인 맞춤으로 설계되어 있음

### 예시 2: 커스터마이징이 쉬움
```
나: "PDCA에서 Check 단계의 합격 기준을 80%로 바꿔줘"

접근 1: bkit.config.json의 matchRateThreshold를 찾아서 수정
         → bkit 코드 구조를 이해해야 함

접근 2: vibecraft.config.json의 합격기준을 수정
         → 내가 직접 설계한 구조라 바로 이해 가능
```

## 장점

1. **깔끔한 코드**: 처음부터 내 스타일로 작성하므로 불필요한 코드 없음
2. **완벽한 한국어**: 코드 주석, 변수명 설명, 에러 메시지까지 한국어
3. **superpowers 업데이트 추적 가능**: 베이스가 단순하므로 원본 업데이트 반영 쉬움
4. **학습 효과**: 직접 만드므로 플러그인 구조를 완벽히 이해하게 됨

## 단점

1. **작업량 최대**: 에이전트 14개, 훅 14개, 템플릿 25개를 새로 만들어야 함
2. **팀 오케스트레이션 재구현**: bkit의 가장 복잡한 부분(lib/team/ 8개 모듈)을 새로 작성
3. **PDCA 상태 관리 구현**: 단계 전환, 자동 반복, 상태 저장 로직 새로 작성
4. **시간 소요**: 완성까지 상당한 시간 필요
5. **버그 위험**: 새로 작성한 코드에 bkit이 이미 해결한 버그가 다시 나올 수 있음
