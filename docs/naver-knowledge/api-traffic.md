# 네이버 트래픽 참조 지식

> **최종 확인일: 2026-03-30**
> 이 문서는 naver-logic-analyzer 에이전트가 트래픽 관련 문제를 진단할 때 참조하는 지식 베이스이다.

---

## 1. 네이버 애널리틱스 (wcslog.js)

### 개요

네이버 애널리틱스는 네이버 블로그, 스마트스토어, 네이버 모두(modoo) 등 네이버 서비스에 기본 내장된 방문자 추적 시스템이다. 외부 사이트에도 스크립트를 삽입하여 사용할 수 있다.

### 추적 코드

```html
<!-- 네이버 공통 추적 스크립트 -->
<script type="text/javascript" src="//wcs.naver.net/wcslog.js"></script>
<script type="text/javascript">
  if (!wcs_add) var wcs_add = {};
  wcs_add["wa"] = "사이트_ID";  // 네이버 애널리틱스에서 발급받은 사이트 ID
  if (window.wcs) {
    wcs_do();  // 페이지뷰 전송
  }
</script>
```

### 수집 데이터

```
[기본 수집 항목]
- 페이지뷰 (URL, 타임스탬프)
- 리퍼러 (어디서 유입되었는가)
- 사용자 에이전트 (브라우저/OS 정보)
- 화면 해상도
- 쿠키 기반 방문자 식별 (신규/재방문)
- IP 주소 (서버 측)

[이벤트 수집 (선택)]
- wcs.event("이벤트명", 값)으로 커스텀 이벤트 추적 가능
- 버튼 클릭, 폼 제출, 특정 영역 도달 등
```

### 네이버 블로그 기본 제공 통계

네이버 블로그는 wcslog.js가 기본 내장되어 있으며, 블로그 관리 페이지에서 아래 통계를 확인할 수 있다:

```
- 방문자 수 (일별/주별/월별)
- 조회수 (글별)
- 유입 경로 (네이버 검색 / 직접 접속 / 외부 링크)
- 유입 키워드 (어떤 검색어로 유입되었는가)
- 방문 기기 (PC/모바일)
```

## 2. 체류 시간 측정 방식

### 측정 원리

```
[페이지 기반 체류 시간]
- 방식: 페이지 A 진입 시각 - 페이지 B 진입 시각 = 페이지 A 체류 시간
- 한계: 마지막 페이지의 체류 시간은 측정 불가 (다음 페이지 이동이 없으므로)

[이벤트 기반 체류 시간 (보완)]
- 일정 간격(예: 15초, 30초)으로 하트비트 이벤트 전송
- 스크롤, 클릭 등 사용자 상호작용 이벤트로 활성 시간 추적
- 페이지 이탈 시(beforeunload) 마지막 이벤트 전송 시도

[네이버 내부 측정]
- wcslog.js가 페이지 진입 시각을 기록
- 페이지 내 사용자 활동(스크롤, 클릭)을 수집
- 네이버 내부 알고리즘으로 실질 체류 시간 계산
```

### 체류 시간 정상 범위

| 체류 시간 | 판정 | 설명 |
|----------|------|------|
| 0~5초 | 바운스 | 콘텐츠를 읽지 않고 이탈 |
| 5~10초 | 짧음 | 제목/도입부만 확인 |
| 10~60초 | 보통 | 콘텐츠 일부 소비 |
| 60~180초 | 양호 | 콘텐츠를 충분히 소비 |
| 180초 이상 | 우수 | 깊이 있는 소비 또는 비활성 |

### 자동화 트래픽에서의 체류 시간

```
[비정상 패턴 — 네이버가 감지할 수 있는 신호]
- 모든 방문의 체류 시간이 동일 (예: 항상 30초)
- 체류 시간이 0~2초 (페이지 로드 즉시 이탈)
- 스크롤/클릭 이벤트 없이 일정 시간 후 이탈
- wcslog.js에 하트비트 이벤트가 전송되지 않음

[정상처럼 보이게 하려면 (회색 지대 경고)]
- 체류 시간에 랜덤 분포 적용 (정규분포 추천)
- 스크롤 이벤트 트리거 (점진적, 자연스러운 속도)
- 클릭 이벤트 발생 (본문 내 링크, 이미지 등)
- 단, 트래픽 조작 자체가 법적 리스크 → 아래 법적 리스크 참조
```

## 3. 이탈률 판별 기준

### 정의

```
이탈률(Bounce Rate) = 단일 페이지 방문 세션 수 / 전체 세션 수 * 100

- 단일 페이지 방문: 사이트에 들어와서 한 페이지만 보고 떠난 경우
- 세션: 사용자의 한 번의 방문 (30분 비활동 시 세션 종료가 일반적)
```

### 판별 기준

| 이탈률 | 판정 | 설명 |
|--------|------|------|
| 0~20% | 매우 낮음 | 비정상적으로 낮을 수 있음 (트래킹 오류 의심) |
| 20~40% | 낮음 (양호) | 사용자 참여도 높음 |
| 40~60% | 보통 | 일반적인 블로그/콘텐츠 사이트 |
| 60~80% | 높음 | 콘텐츠 개선 또는 유입 키워드 미스매치 |
| 80~100% | 매우 높음 | 트래픽 봇 또는 콘텐츠 심각한 불일치 |
| 100% | 비정상 | 모든 방문이 단일 페이지 → 봇 트래픽 의심 |

### 네이버 블로그 특수 사정

```
- 네이버 블로그는 단일 글 조회가 많아 이탈률이 자연스럽게 높음 (60~80%)
- 검색 유입 → 글 한 개 읽기 → 이탈이 일반적 패턴
- 따라서 블로그의 이탈률 100%가 반드시 비정상은 아님
- 다만, 체류 시간이 0~2초 + 이탈률 100%이면 봇 트래픽 강력 의심
```

## 4. 리퍼러 검증 로직

### 리퍼러란

```
리퍼러(Referer) = 현재 페이지에 어디서 왔는지를 나타내는 HTTP 헤더
예: 네이버 검색에서 블로그 글로 유입 → Referer: https://search.naver.com/search.naver?query=...
```

### 정상 리퍼러 패턴

| 유입 경로 | 리퍼러 값 |
|----------|----------|
| 네이버 검색 | `https://search.naver.com/search.naver?...` |
| 네이버 모바일 검색 | `https://m.search.naver.com/search.naver?...` |
| 네이버 메인 | `https://www.naver.com/` |
| 직접 접속 | (리퍼러 없음 또는 빈 값) |
| 외부 사이트 | 해당 사이트 URL |
| 네이버 카페 | `https://cafe.naver.com/...` |

### 비정상 리퍼러 패턴

```
[봇/어뷰징 의심 신호]
- 리퍼러가 항상 동일한 URL (자연스러운 유입이면 다양해야 함)
- 리퍼러가 없는 대량 접속 (직접 접속이 비정상적으로 많음)
- 리퍼러 URL이 존재하지 않는 페이지
- 리퍼러가 네이버 검색인데, 해당 키워드로 검색하면 해당 글이 노출되지 않음
- 리퍼러와 실제 유입 경로 불일치 (HTTP Referer 위조)

[검증 방법]
1. 리퍼러 URL의 도메인이 실재하는가?
2. 리퍼러에 포함된 검색어로 실제 검색 시 해당 글이 노출되는가?
3. 리퍼러 다양성이 자연스러운가? (다양한 검색어, 다양한 페이지)
4. 리퍼러 없는 접속 비율이 비정상적으로 높지 않은가?
```

## 5. 트래픽 진단 트리

에이전트가 트래픽 관련 문제를 진단할 때 아래 트리를 순서대로 따른다.

### 5-1. 접속 패턴 단계

```
[IP 다양성]
├── 모든 접속이 단일/소수 IP에서 발생?
│   ├── YES → 봇 트래픽 강력 의심
│   │   ├── 프록시 로테이션 사용 여부 확인
│   │   ├── 프록시 사용 중이라면 프록시 품질 확인
│   │   │   ├── 데이터센터 IP → 감지 쉬움
│   │   │   ├── 가정용 IP → 감지 어려움
│   │   │   └── IP 블랙리스트 등록 여부 확인
│   │   └── ⚠️ 대규모 프록시 사용 + 봇 감지 우회 = 업무방해죄 가능
│   └── NO → 다음 단계 ↓
│
[User-Agent 다양성]
├── 모든 접속이 동일 UA?
│   ├── YES → UA 로테이션 필요
│   │   ├── UA 풀이 충분한가? (최소 50개 이상 권장)
│   │   ├── UA가 실제 존재하는 브라우저 버전인가?
│   │   └── UA와 요청 헤더 패턴이 일치하는가?
│   └── NO → 다음 단계 ↓
│
[접속 간격 패턴]
├── 접속 간격이 정확히 일정한가? (예: 정확히 5초, 10초)
│   ├── YES → 기계적 패턴 감지됨
│   │   ├── 랜덤 jitter 추가 (기본 간격 +/- 30% 랜덤)
│   │   ├── 가우시안 분포 적용 권장
│   │   └── 시간대별 접속 빈도 변화 적용 (야간 감소 등)
│   └── NO → 다음 단계 ↓
│
[쿠키/세션 연속성]
├── 모든 접속이 새 세션? (쿠키 없음)
│   ├── YES → 비정상
│   │   ├── 쿠키 저장/복원 로직 확인
│   │   ├── NNB 쿠키 유지 여부
│   │   └── 세션 쿠키 연속성 확인
│   └── NO → 일부 재방문 패턴 존재 → 행동 패턴 단계로 ↓
```

### 5-2. 행동 패턴 단계

```
[체류 시간 확인]
├── 체류 시간이 0~5초?
│   ├── YES → 바운스 트래픽
│   │   ├── 페이지 로드 후 즉시 이탈?
│   │   ├── wcslog.js 하트비트 전송 없음?
│   │   └── → 봇 트래픽 또는 콘텐츠 불일치
│   └── NO → 다음 확인 ↓
├── 체류 시간이 항상 동일?
│   ├── YES → 기계적 패턴
│   │   └── 체류 시간에 랜덤 분포 적용 필요
│   └── NO → 다음 확인 ↓
│
[스크롤/클릭 패턴]
├── 페이지 내 스크롤 이벤트 발생?
│   ├── NO → 봇 의심 (사람은 스크롤함)
│   │   ├── Playwright: page.mouse.wheel() 또는 page.evaluate('window.scrollBy()')
│   │   └── 스크롤 속도/패턴을 자연스럽게 (급격한 스크롤 지양)
│   └── YES → 다음 확인 ↓
├── 클릭 이벤트 발생?
│   ├── NO → 콘텐츠 소비 패턴 없음
│   └── YES → 클릭 위치가 자연스러운가?
│
[이탈률 확인]
├── 이탈률 100%?
│   ├── YES + 체류시간 정상 → 블로그 특성상 가능 (단일 글 유입)
│   ├── YES + 체류시간 0~2초 → 봇 트래픽 강력 의심
│   └── NO → 정상 범위 확인 (블로그: 60~80% 정상)
│
[재방문 패턴]
├── 모든 방문이 신규 방문?
│   ├── YES → 비정상 (자연 트래픽이면 일부 재방문 존재)
│   │   └── 쿠키 유지로 재방문자 비율 만들기 → 하지만 어뷰징
│   └── NO → 재방문 비율이 자연스러운가? (10~30% 정도)
```

## 6. IP/UA/접속간격/쿠키 다양성 체크

### 다양성 체크리스트

| 항목 | 정상 기준 | 봇 의심 기준 |
|------|----------|-------------|
| IP 다양성 | 다양한 ISP/지역 | 단일 IP 또는 동일 서브넷 |
| UA 다양성 | 다양한 브라우저/OS 조합 | 단일 UA 또는 2~3개 반복 |
| 접속 간격 | 불규칙, 시간대별 변화 | 정확히 일정한 간격 |
| 쿠키 연속성 | 신규+재방문 혼합 | 항상 새 쿠키 (재방문 없음) |
| 접속 시간대 | 주간 많고 야간 적음 | 24시간 균등 또는 야간에도 동일 |
| 지역 분포 | 서비스 대상 지역 집중 | 의미 없는 지역에서 대량 접속 |

### 상세 체크 방법

```
[IP 체크]
- 동일 /24 서브넷(xxx.xxx.xxx.0~255) 비율 확인
- 데이터센터 IP 여부 (AWS, GCP, Azure IP 대역)
- IP 블랙리스트 조회 (abuseipdb.com 등)
- 국가/지역 분포 확인 (한국 서비스인데 해외 IP 비율 높으면 의심)

[UA 체크]
- UA 문자열이 실존하는 브라우저 버전인가?
- UA와 Accept, Accept-Language 등 헤더 일관성
- 구형 브라우저 UA 비율 (2020년 이전 Chrome 등)
- UA에 "bot", "crawler", "python", "java" 포함 여부

[접속 간격 체크]
- 표준편차 계산 (표준편차가 0에 가까우면 기계적)
- 접속 간격 히스토그램 그리기 (특정 값에 집중되면 봇)
- 최소 간격 확인 (0.1초 이하 간격은 봇)

[쿠키 체크]
- NNB 쿠키 유무 (네이버 브라우저 식별)
- 세션 쿠키 지속 시간
- 동일 쿠키로 반복 접속 비율 (재방문 지표)
```

## 7. 스크롤/클릭/재방문 패턴

### 자연스러운 사용자 행동

```
[스크롤 패턴]
- 페이지 진입 후 1~3초 내 첫 스크롤
- 점진적으로 아래로 스크롤 (한 번에 페이지 끝까지 가지 않음)
- 중간에 멈춤 (읽는 시간)
- 때때로 위로 되돌아감 (재확인)
- 스크롤 속도 불규칙

[클릭 패턴]
- 링크, 이미지, 버튼 등 의미 있는 요소 클릭
- 클릭 위치가 화면 중앙에만 집중되지 않음
- 클릭 간 간격이 자연스러움 (0.5초~수 초)
- 빈 영역 클릭은 드뭄

[재방문 패턴]
- 전체 방문자 중 10~30%는 재방문
- 재방문 간격: 수 시간~수 일
- 재방문 시 이전과 다른 페이지도 조회
```

## 8. 법적 리스크 참조

### 트래픽 어뷰징과 법적 제재

```
[부정경쟁방지법]
- 트래픽 조작(어뷰징)은 부정경쟁행위에 해당할 수 있음
- "부정한 수단으로 경쟁사업자의 고객을 유인하는 행위"
- 손해배상 청구 + 형사 고발 가능

[업무방해죄 (형법 제314조)]
- 대규모 봇 트래픽으로 서버에 부하를 주는 경우
- "허위의 위력으로 사람의 업무를 방해"
- 5년 이하 징역 또는 1,500만원 이하 벌금

[네이버 이용약관 위반]
- 네이버 서비스 이용약관에서 자동화된 수단의 접근 제한
- 약관 위반 시 서비스 이용 제한/계정 정지
- 민사상 손해배상 청구 가능

[실제 사례]
- 블로그 트래픽 조작 업체 적발 → 계정 영구 정지 + 검색 제외
- 대규모 클릭봇 운영 → 업무방해로 형사 고발
- 리뷰/트래픽 조작 대행업체 → 공정거래위원회 제재
```

### 진단 보고서 법적 리스크 항목 (필수)

```
- 현재 자동화의 법적 분류: {합법/회색/불법}
- 위반 가능 법률: {해당 법률}
  - 부정경쟁방지법 (트래픽 조작)
  - 형법 제314조 (업무방해 — 대규모 봇 트래픽)
  - 네이버 이용약관 위반
- 권고: {법적 안전 범위 내 대안}
```

### 합법적 트래픽 증가 방법 (대안 제시용)

```
[합법]
- SEO 최적화 (검색 노출 개선)
- 양질의 콘텐츠 생산
- 네이버 서치어드바이저 활용
- 네이버 광고(공식) 집행
- SNS 공유/홍보

[회색 — 주의 필요]
- 소규모 자체 테스트 트래픽 (모니터링 목적)
- 본인 블로그 접속 패턴 분석

[불법]
- 봇을 이용한 인위적 방문자 수 조작
- 트래픽 조작 대행 서비스 이용
- 클릭봇을 이용한 검색 순위 조작
```
