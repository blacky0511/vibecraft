# 네이버 블로그 API 체계 + 진단 트리

> 최종 확인일: 2026-03-30

---

## 1. 블로그 API 체계

### 1-1. 에디터 분기

네이버 블로그는 두 가지 에디터를 사용한다. 자동화 시 대상 블로그가 어떤 에디터를 쓰는지 먼저 확인해야 한다.

| 에디터 | 기술 스택 | 상태 | 비고 |
|--------|----------|------|------|
| SmartEditor ONE | React 기반, 다중 iframe | 현재 기본 | 대부분의 블로그 |
| SmartEditor 3 (구에디터) | 레거시, 단일 iframe (`se2_iframe`) | 일부 블로그 사용 | 오래된 블로그 설정 |

**SmartEditor ONE 특징:**
- React 기반 SPA로 동작
- 다중 iframe 구조 (`mainFrame` 등)
- 에디터 Ready 이벤트를 기다려야 조작 가능
- 본문 데이터 형식: JSON (Delta 포맷) 또는 HTML
- JS 번들이 로딩 완료된 후에만 에디터 기능 사용 가능

**SmartEditor 3 (구에디터) 특징:**
- `se2_iframe` 단일 iframe 구조
- 레거시 HTML 기반
- 일부 오래된 블로그에서 설정 변경 없이 계속 사용
- 점진적으로 SmartEditor ONE으로 전환 중

**에디터 판별 방법:**
- 에디터 페이지 접근 후 iframe 구조 확인
- `se2_iframe` 존재 → SmartEditor 3
- `mainFrame` 또는 React 컴포넌트 구조 → SmartEditor ONE
- `gnb` (Global Navigation Bar) 로딩 여부로 페이지 정상 로드 판별 가능

### 1-2. 글 작성 API

| 엔드포인트 | 메서드 | 용도 | 비고 |
|-----------|--------|------|------|
| `/RabbitWrite.naver` | POST | 글 발행 (구버전) | SmartEditor 3용 |
| `/editor/mainContent.json` | POST | 글 발행 (신버전) | SmartEditor ONE용 |
| `/editor/save.json` | POST | 임시 저장 | 자동 저장 기능 |
| `/postWriteFormData.naver` | POST | 폼 데이터 방식 발행 | 일부 케이스 |

**요청 필수 항목:**
- CSRF 토큰 (아래 1-4 참조)
- Referer 헤더 (반드시 `blog.naver.com` 도메인)
- 쿠키: `NID_AUT` + `NID_SES` + `NNB` + `BlogUser`
- Content-Type: 에디터 버전에 따라 `application/json` 또는 `application/x-www-form-urlencoded`

**본문 데이터 형식:**
- SmartEditor ONE: JSON Delta 포맷 (에디터 내부 구조)
- SmartEditor 3: HTML 문자열
- 형식이 맞지 않으면 400 또는 500 에러 반환

### 1-3. 이미지 업로드 API

| 엔드포인트 | 메서드 | 용도 |
|-----------|--------|------|
| `/editor/uploadContent.json` | POST (multipart) | 에디터 내 이미지 업로드 |

**업로드 규칙:**
- `multipart/form-data` 형식 필수
- 이미지 업로드 전용 토큰 필요 (에디터 세션 토큰과 별도, 약 10분 만료)
- 파일 크기 제한 존재 (일반적으로 10MB 이하)
- 지원 포맷: JPG, PNG, GIF, BMP, WEBP
- 업로드 성공 시 CDN URL 반환 → 본문에 해당 URL 삽입

### 1-4. 임시저장

- `/editor/save.json`으로 자동 저장
- 에디터 세션 토큰 필요 (약 30분 만료)
- 임시저장 목록 조회 및 복원 가능
- 임시저장과 발행은 별도 API

### 1-5. 카테고리 관리

- 블로그 카테고리는 사용자별 설정
- 글 발행 시 `categoryNo` 파라미터로 카테고리 지정
- 카테고리 목록 조회: 블로그 설정 페이지 또는 에디터 초기화 시 로드
- 존재하지 않는 카테고리 번호 사용 시 기본 카테고리로 발행

## 2. CSRF 토큰, Referer, 쿠키 필수 사항

### 2-1. 에디터 세션 토큰 3종

블로그 에디터에서 글을 작성하려면 3가지 토큰이 모두 필요하다. 각각 만료 시점이 다르므로 주의해야 한다.

| 토큰 | 획득 위치 | 만료 시간 | 용도 |
|------|----------|----------|------|
| CSRF 토큰 | `<meta name="_csrf">` 태그 | 페이지 로드마다 갱신 | 모든 쓰기 API에 필수 |
| 에디터 세션 토큰 | 에디터 iframe 로드 시 발급 | 약 30분 | 에디터 API 전용 |
| 이미지 업로드 토큰 | 이미지 업로드 API 전용 | 약 10분 | 이미지 업로드 전용 |

**CSRF 토큰 추출:**
```
1. 에디터 페이지 로드
2. HTML에서 <meta name="_csrf" content="{토큰}"> 추출
3. 모든 POST 요청의 헤더 또는 파라미터에 포함
```

**토큰 만료 시 증상:**
- 403 Forbidden 또는 CSRF 검증 실패 에러
- 에디터는 로드되지만 발행 버튼 클릭 시 실패
- 이미지 업로드 시 "세션 만료" 에러

### 2-2. Referer 헤더

- 모든 블로그 쓰기 API 호출 시 `Referer: https://blog.naver.com/...` 필수
- Referer 없이 API 직접 호출하면 403 반환
- Referer 도메인이 `naver.com` 계열이 아니면 차단

### 2-3. 쿠키 필수 목록

| 쿠키 | 필수 여부 | 역할 |
|------|----------|------|
| NID_AUT | 필수 | 로그인 인증 토큰 |
| NID_SES | 필수 | 세션 유지 |
| NNB | 필수 | 브라우저 식별 (없으면 봇 의심) |
| BlogUser | 필수 | 블로그 서비스 전용 쿠키 |
| nid_inf | 권장 | 부가 인증 정보 |

**쿠키 체인 순서:**
```
NID_AUT → NID_SES → NNB → BlogUser
이 순서대로 발급되어야 정상. NID_AUT 없이 BlogUser만 보내면 세션 무효화 가능
```

## 3. 스팸 필터 + HTML 콘텐츠 필터링

### 3-1. 스팸 필터

네이버 블로그는 자동화 글 작성을 탐지하기 위한 다층 스팸 필터를 운영한다.

**스팸 판정 기준:**

| 기준 | 설명 | 결과 |
|------|------|------|
| 동일 내용 반복 | 같은 내용을 여러 번 발행 | 발행 거부 또는 비공개 전환 |
| 금지어 포함 | 네이버 내부 금지어 목록에 해당하는 단어 | 발행 거부 |
| 링크 과다 | 본문에 외부 링크가 과도하게 포함 | 스팸 판정 |
| 신규 블로그 제한 | 생성된 지 얼마 안 된 블로그에서 대량 발행 | 발행 속도 제한 |
| 단시간 대량 발행 | 짧은 시간에 많은 글 발행 | 계정 제한 |
| 특정 패턴 반복 | 제목/본문 구조가 기계적으로 동일 | 스팸 의심 |

**스팸 판정 시 대응:**
- 발행 거부: 에러 응답 코드 확인 후 내용 수정
- 비공개 전환: 발행 직후 URL 접근 가능 여부 확인
- 계정 제한: 일정 기간 후 자동 해제 또는 수동 이의 제기

### 3-2. HTML 콘텐츠 필터링

네이버 블로그는 보안 및 사용자 보호를 위해 본문 HTML에서 특정 태그/속성을 자동 제거한다.

**자동 제거 대상:**
- `<script>` 태그 전체
- `<iframe>` 태그 (네이버 자체 iframe 제외)
- `onclick`, `onerror` 등 이벤트 핸들러 속성
- `javascript:` 프로토콜 링크
- 외부 `<style>` 태그 (인라인 스타일은 일부 허용)
- `position: fixed/absolute` 등 레이아웃 조작 CSS

**주의사항:**
- 자동화로 글을 작성할 때 위 요소가 포함되면 조용히 제거됨 (에러 없이)
- 발행 후 실제 글을 확인하면 의도한 내용이 빠져있을 수 있음
- 이미지 태그의 `src`는 네이버 CDN URL만 허용 (외부 이미지 URL은 차단 또는 프록시 처리)

## 4. 블로그 저품질 판정 (패널티 카테고리)

네이버는 검색 품질 유지를 위해 블로그에 저품질 판정을 내릴 수 있다.

### 4-1. 저품질 유형

| 유형 | 증상 | 원인 |
|------|------|------|
| 검색 노출 제한 | 키워드 검색에서 글이 누락됨 | 어뷰징, 스팸성 콘텐츠 |
| 비공개 자동 전환 | 발행한 글이 자동으로 비공개로 전환 | 스팸 필터 트리거 |
| 계정 제재 | 블로그 서비스 이용 자체가 제한됨 | 심각한 이용약관 위반 |
| VIEW 탭 누락 | VIEW 탭(블로그+카페 통합 검색)에서 제외 | 저품질 콘텐츠 판정 |

### 4-2. 저품질 판정 기준 (알려진 패턴)

- 자동화 도구로 대량 발행
- 유사한 구조의 글 반복 발행
- 특정 키워드만 반복적으로 타겟팅
- 외부 링크 비율이 높은 글
- 체류 시간이 극단적으로 짧은 글 (방문자가 바로 이탈)
- 검색 유입만 있고 실제 독자 없음
- 다른 블로그에서 복사한 내용 (중복 콘텐츠)

### 4-3. 저품질 확인 방법

```
1. 자신의 글을 네이버에서 제목으로 검색 → 노출 안 되면 저품질 의심
2. VIEW 탭에서 검색 → 누락되면 VIEW 저품질
3. 블로그 관리 → 통계에서 검색 유입 급감 확인
4. 네이버 웹마스터 도구(서치어드바이저)에서 색인 상태 확인
```

### 4-4. 저품질 해제

- 명확한 해제 절차는 공식적으로 존재하지 않음
- 일반적으로 1~3개월 양질의 콘텐츠 발행 후 자연 해제
- 문제되는 글 삭제 또는 비공개 처리
- 자동화 완전 중단 후 수동 운영으로 전환

## 5. 블로그 진단 트리

### 5-1. 로그인 단계

```
nid.naver.com 접근 가능?
├── NO → DNS/네트워크 문제 → 네트워크 렌즈
│   ├── DNS 확인: nslookup nid.naver.com
│   ├── 포트 확인: 443 포트 접근 가능한지
│   └── 프록시/VPN 설정 확인
└── YES ↓

로그인 페이지 HTML 정상 로드?
├── NO → JS 의존 요소 미로드 → 브라우저 렌즈
│   ├── 로그인 폼은 JS로 렌더링되므로 JS 실행 환경 필수
│   ├── headless 브라우저에서 JS 실행 확인
│   └── CSP(Content Security Policy) 차단 여부
└── YES ↓

RSA 공개키 발급? (keys_v2 API 또는 HTML 내 포함)
├── NO → API 변경 → API 렌즈
│   ├── keys_v2 엔드포인트 URL 변경 확인
│   ├── 공개키 포맷 변경 확인
│   └── 응답 스키마 변경 확인
└── YES ↓

encData 생성 성공?
├── NO → RSA 암호화 로직 오류 → 보안 렌즈
│   ├── sessionKey 형식 변경?
│   ├── 암호화 알고리즘 변경? (enctp 값 확인)
│   ├── 키 길이 변경?
│   └── JS 번들(lnm.js 등)에서 최신 로직 추출 필요
└── YES ↓

bvsd 토큰 생성?
├── NO → 행동 데이터 수집 안 됨 → 자동화 렌즈
│   ├── 마우스/키보드 이벤트 시뮬레이션 확인
│   ├── 타임스탬프 간격이 자연스러운지
│   └── 이벤트 순서의 인과성 (mousedown → mouseup)
└── YES ↓

로그인 POST 요청 → 응답 코드?
├── 200 + 쿠키 발급 → 로그인 성공 → 에디터 접근 단계로
├── 200 + captcha → 캡차 트리거됨
│   ├── bvsd 품질 저하?
│   ├── 동일 IP 반복 로그인 시도?
│   └── 봇 감지 스코어 높음?
├── 200 + new_device → 기기 인증 필요
│   ├── 저장된 deviceId 복원 확인
│   ├── NID_JKL 쿠키 복원 확인
│   └── 2차 인증 방식 확인 (SMS/OTP/앱)
├── 200 + QR/원터치 강제 → 네이버 앱 인증 필요
│   └── 신규 기기 + 고위험 상황에서 발생
├── 403 → IP 차단
│   ├── 일반 403 vs WAF 커스텀 에러 페이지 구분
│   └── IP 변경 또는 프록시 전환 필요
└── 302 → 리다이렉트 추적
    └── 리다이렉트 체인 확인 (최종 목적지)

NID_AUT + NID_SES + NNB 쿠키 정상 발급?
├── NO → 쿠키 체인 확인
│   ├── 쿠키 도메인 스코프 변경 (.naver.com → 서브도메인)?
│   ├── SameSite 정책 변경 (Lax → Strict)?
│   └── 쿠키 순서 의존성 확인
└── YES ↓

2차 인증 / Naver Guard 통과?
├── YES → 에디터 접근 단계로
└── NO
    ├── 저장된 인증 토큰 복원 확인
    ├── deviceId 영구 저장 및 복원 확인
    └── 2차 인증 자동화 가능 여부 검토
```

### 5-2. 에디터 접근 단계

```
에디터 타입 분기:
├── SmartEditor ONE (현재 기본)
│   ├── React 기반, 다중 iframe 구조
│   ├── mainFrame 로드 대기 필요
│   └── 에디터 Ready 이벤트 확인
└── SmartEditor 3 (구에디터)
    ├── se2_iframe 단일 iframe 구조
    └── 레거시 API 사용

에디터 세션 토큰 3종 발급?
├── NO → 각 토큰 만료 시점 확인
│   ├── CSRF 토큰: 페이지 재로드로 갱신
│   ├── 에디터 세션: 에디터 재진입 필요 (30분 만료)
│   └── 이미지 업로드: 별도 갱신 (10분 만료)
└── YES ↓

CSRF 토큰 확인?
├── NO → 확인할 사항:
│   ├── meta 태그 위치/이름 변경?
│   ├── <meta name="_csrf"> → 다른 이름으로 변경?
│   └── 토큰 전달 방식 변경 (헤더 vs 파라미터)?
└── YES → 포스팅 API 단계로
```

### 5-3. 포스팅 API 단계

```
본문 데이터 포맷 확인
├── SmartEditor ONE → JSON (Delta 포맷) 또는 HTML
├── SmartEditor 3 → HTML 문자열
└── 포맷 불일치 시 400/500 에러

이미지 업로드 API 정상?
├── NO → 확인할 사항:
│   ├── 이미지 업로드 토큰 만료?
│   ├── multipart/form-data 형식 오류?
│   ├── 파일 크기 초과?
│   └── 지원하지 않는 파일 포맷?
└── YES ↓

발행 API 요청 → 응답?
├── 성공 → postId 반환
├── 실패 → 에러 코드 분석
│   ├── CSRF 토큰 만료 → 재발급 필요
│   ├── 파라미터 변경 → API 렌즈
│   ├── 500 에러 → 서버 측 문제 / 데이터 포맷 오류
│   └── 인증 실패 → 쿠키/세션 재확인
└── 차단 → 스팸 판정
    ├── 동일 내용 반복?
    ├── 금지어 포함?
    ├── 링크 과다?
    ├── 신규 블로그 제한?
    └── HTML 콘텐츠 필터링 (특정 태그/속성 자동 제거)?

발행 후 URL 접근 가능?
├── NO → 비공개 전환 (스팸 필터)
│   └── 글 내용 점검 필요
└── YES ↓

블로그 저품질 판정 (패널티)?
├── 검색 노출 제한 → 키워드 검색에서 누락
├── 비공개 자동 전환 → 글 목록에서 확인
└── 계정 제재 → 블로그 서비스 이용 제한
```

## 6. 법적 리스크 참조

블로그 자동화와 관련된 법적 리스크는 행위의 성격에 따라 달라진다.

| 행위 | 분류 | 관련 법률 | 비고 |
|------|------|----------|------|
| 본인 블로그 관리 자동화 | 합법 (Green) | - | 자기 콘텐츠 관리 |
| 비공식 API로 글 작성 | 회색 (Yellow) | 네이버 이용약관 | 계정 잠금 리스크 |
| 대량 자동 포스팅 (어뷰징) | 불법 (Red) | 형법 314조 (업무방해) | 5년 이하 징역 |
| 캡차 우회 서비스 사용 | 불법 (Red) | 정보통신망법 48조 | 5년 이하 징역 |
| 타인 계정 사용 | 불법 (Red) | 정보통신망법 49조 | 5년 이하 징역 |
| 가짜 블로그 리뷰 작성 | 불법 (Red) | 공정거래법, 표시광고법 | 과태료 최대 2억원 |

> 진단 보고서에는 반드시 현재 자동화의 법적 분류를 포함해야 한다.
> 불법(Red)에 해당하는 행위를 발견하면 즉시 경고하고 대안을 제시한다.
